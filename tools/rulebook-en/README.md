# 英語版ルールブックの原稿とビルド

印刷版ルールブック（`data/rulebooks/` のページ画像）を英語にした PDF を作る仕組み。翻訳の方針と用語集は [docs/publishing/rulebook-en.md](../../docs/publishing/rulebook-en.md)。この文書は「1 シートの原稿を書いて確認する」ための手引き。

- 方式: 原本のページ画像をそのまま下地にし、**日本語の文字だけを背景と同じ模様・色の四角で覆い、同じ位置に英語の HTML テキストを重ねる**。図・枠・見出しの帯・ページ番号は原本のまま。ヘッドレス Chrome で PDF にする（文字はベクターのまま、選択・検索できる）。
- 必要なもの: 作者の手元の `data/`（Git 管理外。ワークツリーでは `../../data` へのシンボリックリンク）、macOS の Google Chrome（既定のパス。別の場所なら環境変数 `CHROME_PATH`）、Node（親ディレクトリの `node_modules` の `sharp` を使う。`npm install` は不要）。
- 成果物は `build/rulebook-en/`（Git 管理外）。原本の図版を含むのでコミットしない。

## 1. 1 シートを書いて確認する手順

1. 担当シートを決める（シート ID は下の表）。`tools/rulebook-en/pages/<ID>.html` を作る（無ければ下地だけのページになる）。
2. 原本を領域ごとに拡大して読む（Read ツールは大きな画像を縮小するので、ページ全体のままだと小さい字を読み違える）:

   ```bash
   node scripts/rulebook-en-crop.mjs p04 60 260 1640 330 --zoom 1 --grid 50
   ```

   `build/rulebook-en/tmp/` に目盛り付きの画像ができる（座標は原本 PNG のピクセル）。
3. 文字・図の位置を測り、消す四角と英語の文字の箱を書く（第 3・4 節）。
4. ビルドして原本と見比べる:

   ```bash
   node scripts/build-rulebook-en.mjs --only p04 --png          # partial/p04.pdf と preview/p04.png
   node scripts/build-rulebook-en.mjs --only p04 --png --debug  # 箱の枠を表示
   ```

5. 確認（第 7 節）。はみ出しの報告が出たら言い回しを短くする。

全シートを通しでビルド（`npm run build:rulebook-en` と同じ）:

```bash
node scripts/build-rulebook-en.mjs   # build/rulebook-en/PROJECT-EDGEWORTH-Rulebook-EN.pdf（22 ページ）
```

通しのビルドは、シートごとに印刷した PDF（`--only` の `partial/<ID>.pdf` と同じもの）を `scripts/lib/pdf-merge.mjs` で 1 つに結合する（依存パッケージなし）。幅の違うページ（単ページ 420 pt・見開き 839 pt）を 1 回の印刷に混ぜると Chrome が全ページのレイアウトを崩すため。結合は、ページから届くオブジェクトだけを集めて番号を振り直し、ページごとの寸法を保つ。想定と違う PDF（オブジェクトストリームがある、`/Length` と合わない、など）のときは、壊れた PDF を出さずにエラーで止まる。文書のタイトルは "PROJECT EDGEWORTH Rulebook (English)"。出力先が先に閉じられても（`| head` など）最後まで走り、Chrome の一時ディレクトリは必ず消える。

| オプション | 意味 |
| --- | --- |
| `--only p04,p12` | 指定シートだけを `build/rulebook-en/partial/<ID>.pdf` に出す（担当者が並行で回しても他人の出力を上書きしない） |
| `--png` | `build/rulebook-en/preview/<ID>.png` に確認用の画像を出す。**原本 PNG と同じ画素寸法・同じ座標系（塗り足し込み）** なので、原本と同じ座標で見比べられる |
| `--debug` | 文字の箱（マゼンタの実線）と消す四角（緑の破線）に細い枠を出す |
| `--scale 0.8` `--quality 80` | 下地の縮小率と JPEG の品質（第 8 節） |

環境変数 `RULEBOOK_OUT_DIR`（出力先）と `RULEBOOK_PAGES_DIR`（原稿の置き場）で、他の担当者の出力と原稿に触れずに部品を試せる（例: `RULEBOOK_OUT_DIR=build/rulebook-en-test RULEBOOK_PAGES_DIR=build/rulebook-en/tmp/testpages node scripts/build-rulebook-en.mjs --only p03 --png`）。

毎回、文字の箱ごとの指定サイズ・最終サイズ・はみ出しを標準出力と `build/rulebook-en/report-<ID>.json` に出す（Chrome で `fit.js` を実行した後の値）。

### シート ID

## 2. 座標系と仕上がり枠

- 座標・大きさはすべて **原本 PNG のピクセル（左上が原点、塗り足しを含む）**。原本は 288 dpi（1 pt = 4 px）。本文の文字は約 38 px（9.5 pt）。フォントサイズも原本 px（36 px = 9 pt）。
- 単ページの PNG は 1747×2450 px。画像に焼き込まれた赤い細線の内側 36 px からが仕上がり（x 36〜1710、y 36〜2412）。赤線と塗り足しは PDF に出ない（`--png` の確認画像には塗り足しごと出るので、赤線も見える）。
- 見開きの仕上がりは x 36〜3389、y 36〜2412（四隅の飾りを単ページと突き合わせて決めた。根拠は `sheets.mjs` のコメント）。`p10-11` は 3471 px 幅、`p14-15` は 2474 px 高だが、余りは余白で PDF に出ない。
- 出力ページは単ページ 420×595 pt（148.17×209.89 mm、A5 を Chrome が整数 pt に丸めた値）、見開き 839×595 pt（295.99 mm 幅）。

## 3. 測り方（`scripts/rulebook-en-crop.mjs`）

| 目的 | コマンド（`<ID> x y w h` は領域） |
| --- | --- |
| 拡大して読む・目盛りで座標を読む | `crop.mjs p04 60 260 1640 330 --zoom 1.5 --grid 50`（`--grid 10` で細かく） |
| 文字の行の位置・高さ・左右の範囲 | `crop.mjs p04 90 1100 560 800 --bbox`（明るい画素の行ごとの外接矩形。図と重なる領域だと混ざるので文字だけの領域に絞る） |
| 表の罫線の位置 | `crop.mjs p04 640 1180 1020 1080 --lines --min 150`（太さの分だけ連続した座標が並ぶ。セルの内側は罫線の次の座標から） |
| 札・箱の中の黒い文字の範囲 | `crop.mjs p12 90 906 520 60 --dark`（札の中の文字だけ消して ▼ は残す、といった範囲決め） |
| 単色の箱・文字の色 | `crop.mjs p12 100 1375 60 50 --colors`（代表色。4 刻みに丸めた値） |
| 帯や箱の端、縞の位置 | `crop.mjs p04 --scan x 95 270 400`（x=95 に沿って同色が続く区間。札の上端・下端を正確に出せる） |

`crop.mjs` は `node scripts/rulebook-en-crop.mjs` の略。**画像を目で見て決めた座標より、数値で測った座標を使う**（拡大表示の縮尺は思ったより当てにならない。p04・p12 でも札の高さを目測で誤った）。

## 4. 原稿の書き方

`pages/<ID>.html` は HTML の断片（`<html>` などは書かない）。ページの左上が原点で、要素は `--x` `--y` `--w` `--h`（原本 px）で絶対配置する。`<script>` は書かない。見本は [pages/p04.html](pages/p04.html)（表・引き出し・縞の地）と [pages/p12.html](pages/p12.html)（図・番号つきの手順・色つきの語）。

### 消す四角 `.e`

```html
<div class="e" style="--x:96;--y:366;--w:1540;--h:182"></div>                       <!-- 縞の地を再現して覆う -->
<div class="e flat f-gray" style="--x:960;--y:162;--w:595;--h:51"></div>             <!-- 単色で覆う -->
<div class="e flat" style="--x:100;--y:200;--w:50;--h:50;--c:#6b6b6b"></div>         <!-- 任意の単色 -->
```

- 既定は**ページの地の縞模様**。縞は原本の画像から測って再現するので、**ページの地の上でだけ**使える（色付きの箱・カードの上で使うと縞が出てしまう）。見開きは左右のページで縞の位相が違うが、`fit.js` が四角の中心の位置で左右を選ぶ。
- 色付きの箱・札・帯の上は `flat`。色は `--c`（任意）か `f-cyan`（見出しの札の青）、`f-gray`（見出しの札・図の箱の**明るい灰色** #cccccc）、`f-blue` `f-yellow` `f-green` `f-red` `f-purple` `f-orange`（フェイズの箱の色）、`f-numgray`（灰色の番号札 #656767）。色は `--c` で必ず測る（`--colors`）。
- **`f-gray` は見出しの札・図の箱の明るい灰色で、例の箱（灰色の大きな面）の灰色とは違う。** 例の箱の上は `--c:#656767`（`f-numgray` も同じ色）。

担当者が測った、よく使う単色（原本から拾った値。ほかの値は各ページの原稿の `--c` を参照）:

| 色 | 値 | どこで使うか |
| --- | --- | --- |
| 例の箱の灰色 | `#656767` | 例・解説の灰色の大きな面（p08・p09・p21 ほか）。`f-numgray` と同じ |
| 六角の札の青 | `#1d2088` | 得点計算例の六角形の札 |
| 六角の札の紫 | `#723891` | 得点計算例の六角形の札 |
| 見出しの札の水色 | `#26a7e1` | `f-cyan` |
| 見出しの札・図の箱の灰色 | `#cccccc` | `f-gray`（例の箱の灰色とは別） |

- 角の丸みは `--r`（px）。**四角は罫線・図・ほかの文字にかけない**（消したい文字の外周より 2〜4 px 広い程度に）。
- 縞の地は、水平な 1 px の明るい線が約 20.4 px 間隔で入った模様（周期 20.4 px。画像の座標に合わせて再現）。線の上に端が来ても跡は出ない。

### 文字の箱 `.t`

```html
<div class="t" style="--x:100;--y:368;--w:1535;--h:178;--fs:32;--lh:1.55">English text with <span class="cy">emphasis</span>.</div>
<div class="t e c vm" style="--x:112;--y:1923;--w:119;--h:122;--fs:28">Area<br>Cost</div>   <!-- 消す四角を兼ねる -->
```

| 変数 | 意味（既定） |
| --- | --- |
| `--x` `--y` `--w` `--h` | 位置と大きさ（原本 px）。`--h` を超えるとはみ出し扱い（自動縮小の対象） |
| `--fs` | フォントサイズ（31）。原本 px |
| `--lh` | 行間（1.45）。単位なしの倍率 |
| `--ls` | 字間（0）。em 単位の倍率（`0.1` = 0.1 em） |
| `--fit-min` | 自動縮小の下限（0.85 = 指定値の 85%）。`nofit` クラスで自動縮小を止める |
| `--pg` | `<p>` どうしの間隔（0.4 em） |
| `--c` | `class="ct"` を付けたときの文字色 |

| クラス | 意味 |
| --- | --- |
| `c` `r` `j` | 中央揃え・右揃え・両端揃え（既定は左揃え） |
| `vm` `vb` | 縦に中央・下に寄せる（既定は上）。1 行の札・セルの中で使う |
| `nw` | 折り返さない（`.t` に付けると箱全体、文中の `<span class="nw">…</span>` に付けるとその範囲だけ） |
| `vert` | 縦書き（図の縦長の帯。文字は右に 90 度回る）。`--lh` は帯の幅に合わせて小さく（帯 44 px なら 40 px の文字で `--lh:1.1`） |
| `b7` `b8` | 太さ（既定は 700。800 は見出しの札・図の箱の中） |
| `fh` | 小見出し用の書体 Chakra Petch 700 |
| `fband` | 見出しの帯の直し用の書体 Black Ops One（原本の「CONTENT」「SETUP」の帯の書体に近い）。p28 の綴りの直しなどに使う |
| `up` | 大文字にする |
| `e` | 消す四角を兼ねる（箱と同じ位置・大きさ。`flat` `f-色` も併用できる） |

文字の色は `.t` にも文中の `<span>` にも付けられる: `cy`（強調の水色）、`yl`（薄い黄）、`gr`（薄い緑）、`pk`（ピンク）、`pu`（薄い紫）、`or`（薄い橙）、`dk`（暗い文字。灰色・色付きの箱の中）、`wh`、`cgray`。

プレイヤー名の色（原本の色）: `<span class="teresa">Teresa</span>`（青）、`lily`（黄）、`jessie`（緑）、`luna`（赤）。

**消す四角と文字の箱を分けるとき**: 英語が日本語より長い箱は、`<div class="e">`（日本語を消す範囲）と `<div class="t">`（英語。必要なら消す範囲より大きい）を別に書く。`.t.e` は両方が同じ位置・大きさ。

### 箇条書き

```html
<div class="li" style="--ind:2"><span class="n">1.</span>Return the sideways Action Card to your hand.</div>
```

`--ind`（em）で数字の幅を決め、折り返した行が本文の頭にそろう。

### 番号札（インライン部品）

原本の番号札（赤・青・灰色の四角）は**画像のまま残す**。文章の途中に置くとき用に同じ見た目の部品がある: `<span class="nt red">1</span>`（赤地に白）、`nt blue`（青地）、`nt gray`（灰色）、`nt white`（白地に黒）。

文中で図の丸数字を指すときは `<span class="cn">1</span>`（CSS で描く丸数字）を使う。`①` などの文字は同梱フォントに字形が無く、ビルドする環境のフォントで代用されてしまうので使わない。

### 見出しの札（水色・灰色）

札の形・▼ は原本の画像のまま、中の日本語だけを消して英語を置く（p04・p12 の見本）:

```html
<div class="t e flat f-cyan fh dk vm" style="--x:96;--y:295;--w:290;--h:54;--fs:40;--lh:1.1">Region Board</div>
```

`--x` は文字の左端の少し手前、`--w` は ▼ の手前まで（`--dark` で測る）。札の高さの中に `--lh` を 1.1 前後にして収める（既定の 1.45 だと 1 行でも高さを超えてはみ出し扱いになる）。

### インラインのアイコン

`<i class="ic NAME"></i>`。高さは文字の 1.15 倍で、行の高さを乱さない（`vertical-align` 済み）。大きくしたいときは `style="--ich:1.6em"`。

**数字入りの名声** は `<i class="ic fame">5</i>`。五角形の高さは `--ich`（既定 **1.6em**。本文中で数字が読める大きさ）で、`style="--ich:1.7em"` のように指定する。従来どおり `style="font-size:1.7em"` を付けたものは、その font-size を基準に高さ 1.15 倍になる（見た目は変わらない）。上下の余白を負にしてあるので、大きくしても行の高さは変わらない（`--lh:1.55` の本文 32 px、`--lh:1.5` の 28 px の箱で、fame のある行とない行の行間が同じことを確かめた）。数字は原本と同じく五角形いっぱいに大きく（1 桁は五角形の高さの約 7 割、2 桁は幅が五角形とほぼ同じ。2 桁は自動で少し小さくなる）、書体は 1・7・0 の字形がはっきりした Chakra Petch 700。読みやすさのため紫がかった暗色の薄い縁取りを付けている。

| クラス | 中身 | 出どころ |
| --- | --- | --- |
| `maya` `maya-spend` `maya-gain` | マヤ（丸）・マヤ消費・マヤ獲得 | `data/icons/` |
| `budget` | 予算（四角い枠つきのマヤ） | `data/icons/予算` |
| `fame` | 名声（五角形 + 数字を文字で重ねる） | `data/icons/名声` |
| `cost` `fuel` | コスト、燃料 | `data/icons/` |
| `crew` `device` `software` | プロジェクトの種別 | `data/icons/` |
| `star` `dagger` `all` | 星、短剣、ALL | `data/icons/` |
| `tm-budget` `tm-deploy` `tm-launch` `tm-turn` `tm-link` `tm-proposal` `tm-orbit` | 効果発動タイミング（予算発行・配備・打ち上げ・転回・通信確立・企画・循環） | `data/icons/` |
| `constant` `activated` | 効果タイプ（常時・起動） | `data/icons/` |
| `region-a`〜`region-h` | 地域アイコン A〜H | `data/icons/area_*` |
| `hex-sea` `hex-deep-sea` `hex-reef` `hex-land` `hex-forest` `hex-mountain` `hex-snowfield` | 区域の種類ごとの六角形 | `data/boards/area/` |
| `plan-a` | 計画フェイズ中の「A」（黒い八角形） | p27 から切り出し |
| `active` `inactive` | 稼働条件の青緑の二重丸・灰色の丸 | p27 から切り出し |

足りないアイコンは `tools/rulebook-en/assets.mjs` に足す。ページ画像から切り出すときは `{ page: 'p27', x, y, w, h, keyOut: true }`（原本の座標。`keyOut` は地の暗い縞の色を透明にする）。ビルドのたびに `build/rulebook-en/assets/` へ書き出され、`icons.css` が自動で作られる。**ほかの担当者と同じ `assets.mjs` を触るので、足した行だけをコミットすること。**

## 5. 文字の大きさ

- 原本の本文は約 38 px。英語は**本文 32 px（行間 `--lh:1.55`）**、図の注釈・引き出しは 30 px、表の見出し・名称 28 px、表の説明 27 px、見出しの札 38〜40 px を見本に合わせる。
- **同じページの同じ役割の文字は同じ大きさにそろえる。** 自動縮小に頼って箱ごとにばらばらにしない（報告の「縮小」が 0 になるのが理想）。26 px（6.5 pt）より小さくしない。収まらないときは意味を変えずに言い回しを短くする。
- 自動縮小（`fit.js`）は、箱の中身が `--h` を超えたらフォントサイズを 0.5 px ずつ下げて収める（下限は指定値の 85%）。それでも収まらない箱は報告に「はみ出し」と出て、`--png` ではその箱が赤い太枠で示される。

## 6. 原本から変えてはいけないところ

罫線・図・番号札・見出しの帯（「CONTENT DETAILS」「HOW TO PLAY」は元から英語）・ページ番号・カードやコマの画像の中の日本語は**原本のまま**。ルールを足さない・削らない・直さない。読み取れない文、二通りに読める文は推測で訳さず報告する。

## 7. 確認のしかた（必ずやる）

`--png` の結果を原本と見比べる。全体を縮小して 1 回、さらに領域ごとに等倍で、次を確かめる。

- (a) 日本語の消し残し（字の縁の欠片が数 px 残りやすい。消す四角は文字の外周より 2〜4 px 広く）
- (b) 消した跡（縞のずれ、色の違い、箱の縁・罫線・図を削ってしまった所、セルの左端の欠片）
- (c) 文字のはみ出し・重なり
- (d) 図や引き出し線とのずれ

並べて見るには次のような一時スクリプト（`build/rulebook-en/tmp/` に置く）が便利:

```js
import sharp from 'sharp';
const ex = { left: 640, top: 540, width: 1010, height: 540 };
const a = await sharp('data/rulebooks/p4@4x.png').extract(ex).png().toBuffer();
const b = await sharp('build/rulebook-en/preview/p04.png').extract(ex).png().toBuffer();
await sharp({ create: { width: 2028, height: 540, channels: 3, background: '#f0f' } }).composite([{ input: a, left: 0, top: 0 }, { input: b, left: 1018, top: 0 }]).png().toFile('build/rulebook-en/tmp/cmp.png');
```

PDF は `pymupdf` などで開いて、ページ数・寸法・英語が文字として取り出せること・フォントが埋め込まれていることも確かめる。

## 8. 下地の画質と PDF の大きさ

下地は原本 PNG を 0.8 倍（約 230 dpi 相当）に縮め、JPEG 品質 80（mozjpeg、クロマサブサンプリングなし）にする。カードの中の小さな日本語が読め、全 22 シートの原稿が入った通しの PDF で約 13.8 MB（14.5 MB 未満）になる。下地だけの状態で測ると、0.85 倍で約 14.4 MB、0.9 倍で約 15.6 MB、等倍（品質 78）で約 17.2 MB だった。上限の 15 MB に余裕を持たせるため 0.8 倍を既定にした。

縞の見本は、実際に PDF に入る JPEG（縮小・圧縮後）から採る。消した跡と周りの縞が同じ解像度・同じ劣化になるので、境目が見えにくい。作り方（`scripts/build-rulebook-en.mjs` の `stripeProfile`）:

1. 地の色は「暗い地（35,25,22 付近）」「明るい線（89,93,103 付近）」と、その間の混ざった色（縮小で滲んだ線の縁）だけ。この 2 点を結ぶ線分に近い画素だけを「地」とみなす。カードの暗い青緑、灰色や青の箱、飾りの紺は地とみなさない。
2. 幅 30 px の帯ごとに、上下 1 行も含めて地だけの行を探し、3 本以上の帯で一致した色をその行の実測値にする。表の罫線・文字・図の周りの行は実測できない。
3. 実測できた線の位置から、線の間隔（原本で 20.4 px）の等間隔の並びを当てはめ、実測した線の断面（中心からの距離ごとの色）を平均する。ページの途中で位相がずれていても、つながる塊ごとに当てはめる。
4. 当てはまったページは、全行をこの並びと断面から作る（実測の行には、罫線の縁など線の色に見える偽の線が混ざるため）。当てはまらないページ（縞の地がほとんど無い、灰色・青の大きな面のページ。p01、p13、p14-15、p16-17 の右、p18-19、p22-25 など）は、実測できた行だけを使い、残りは暗い地の色にする。**そうしたページで縞の四角を使うときは、使う範囲の縞が合っているか必ず目で確かめる。**

縞の見本は `build/rulebook-en/bg/<ID>-l.png`（見開きは `-r` も）。8 px 幅の縦長画像で、1 行が下地 JPEG の 1 行に対応する。

## 9. よくある失敗

| 症状 | 原因と対処 |
| --- | --- |
| 消した範囲の縁に日本語の欠片が残る | 字の外周より広く消していない。`--bbox` で測り直す。セルの中の字は、罫線の太さ（3〜4 px）の分を除いたセルの内側全体を消す |
| 消した範囲に縞の線がずれて見える | 縞の地でない所（色付きの箱）に縞の四角を使った。`flat` と色にする |
| 灰色・色付きの箱の上で消した所の色が違う | `--c` の色が違う。`--colors` で測る |
| 1 行なのにはみ出しと報告される | `--lh`（既定 1.45）× `--fs` が `--h` より大きい。`--lh:1.1` にするか `--h` を広げる |
| 文字の箱が縮小される | 箱が狭い。箱を広げる（図・罫線にかからない範囲で）か言い回しを短くする。ほかの箱とサイズがばらばらにならないようにする |
| 英語の末尾が消した範囲より外にはみ出し、元の絵に重なる | 消す四角と文字の箱を分け、文字の箱が空いている場所だけを使うようにする |
| `--only` で出した PDF に他シートが無い | 仕様どおり。通しのビルドは引数なし |
| 2 桁の名声の数字が五角形から出る | `fame` は 2 桁でも収まるよう自動で小さくなる。3 桁は想定していない |
| 引用符の中の句読点 | アメリカ英語の流儀（“…,” “…。” の句読点は引用符の内側）で書く。強調の水色は引用符ごと包む |
