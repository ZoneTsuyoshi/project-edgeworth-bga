## 目的

紙のゲームでは、物理的な操作（アクションカードを伏せて置く、衛星コマ・キューブを一斉に置く、カードを傾けて使用済みを示す、いつでもカードを捨てて換金する、ボード外にキューブを置いて放棄する、燃料コマをずらす）で意思表示をしている。これらを BGA 上でどんな操作・表示・確認フローにするかを決める。作者の確定事項（rule-questions.md の Q-09〜Q-17）に従い、操作ごとに「紙での操作 / BGA での操作手順 / 他プレイヤーへの見え方 / 取り消し可否 / タイムアウト・zombie 時の既定動作」を定める。

## スコープ

- 対象: 同時選択（アクションプロット、打ち上げ / 転回、通信確立、配備、企画、ボーナス）の操作・表示・確定と取り消し、売却と支払い不足の促し、起動効果の [Use] / [Skip] と使用済みマーク、効果の選択の同時 UI と自分の効果の順番の選択、非公開情報の見え方、燃料の表示、マリガン・ドラフトの操作、「確認」ボタンの方針、各操作の zombie 時の既定動作
- 対象外: 状態の ID・遷移・`MULTIPLE_ACTIVE_PLAYER` の使い方の確定（→ 009）、画面の配置・カード画像・スプライト・モバイル対応の詳細（→ 012）、効果の処理順と「順番が結果を変える」かの判定（→ 007）、DB スキーマ・通知の詳細（→ 010）、個々のカード効果の実装（→ 011）、ルール自体の定義（→ 001）

### 1. BGA の仕組みの確認結果

調査日 2026-10-19。BGA の公式ドキュメントを取得して確認した。**API は更新が速いので、実装時に再確認すること。**

| No. | 確認した事実 | 出典 |
| --- | --- | --- |
| B1 | `setAllPlayersMultiactive()` で全員をアクティブにする。`setPlayerNonMultiactive($playerId, 'transition')` で 1 人を非アクティブにし、**アクティブなプレイヤーがいなくなると、指定の遷移を自動で行う**。複数アクティブ状態では、プレイヤーを「いつでも」アクティブ / 非アクティブにできる | <https://en.doc.boardgamearena.com/Your_game_state_machine:_states.inc.php> |
| B2 | 上記ページには、複数アクティブ状態で選択を取り消す（変更する）ための直接の手順は書かれていない。private parallel states の節に「全員を前の状態へ戻すと他の人の流れを止める」「`actChangeMind` のような操作は、プレイヤーが private 状態にいないときだけ許可できる」という記述がある。順番外の操作（例: Un-pass）は Studio Cookbook を参照し、使いすぎないよう注意されている | 同上 |
| B3 | 組み込みの Undo は `gameinfos` の `db_undo_support` を `true` にし、`undoSavepoint()` で保存する。**保存点は 1 つだけ**で、**複数アクティブ状態、および次の状態が複数アクティブの状態では使えない** | <https://en.doc.boardgamearena.com/Main_game_logic:_Game.php> |
| B4 | 多段の入力は、クライアント状態（`this.bga.states.setClientState`）で集め、最後にサーバーへ送る。`restoreServerGameState()` で最後のサーバー状態へ戻せる（「安価な Undo」）。サーバーへの操作は `this.bga.actions.performAction(action, args, options)`（ユーザー操作への応答としてのみ呼ぶ。`onEnteringState` などから呼ばない） | <https://en.doc.boardgamearena.com/Game_interface_logic:_yourgamename.js> |
| B5 | ステータスバーのボタンは `this.bga.statusBar.addActionButton(label, callback, params?)`、文言の更新は `this.bga.statusBar.setTitle`。ボタンは `onUpdateActionButtons(stateName, args)` で作る。複数アクティブ状態では、`onEnteringState` と `onUpdateActionButtons` の呼ばれる順が予測しにくいため注意が必要 | 同上 |
| B6 | 確認ダイアログ（`this.bga.dialogs.confirmation(message)`）は**一般に避ける**（遊びが遅くなる）。まれにしか起きず、誤クリックで「ゲームを壊しうる」うえ、誤って押しやすい操作に限る | 同上 |
| B7 | プレイヤーパネルは `this.bga.playerPanels.getElement(playerId)` で取得し、独自の表示を挿入できる。数値は `ebg/counter` で管理する | 同上 |
| B8 | 各状態クラスに `zombie(int $playerId)` が必要。zombie の処理では `getCurrentPlayerId()` を使えず、`$playerId` を使う。複数アクティブ状態では、zombie の処理の後に `setPlayerNonMultiactive` で非ブロッキングにする（姉妹リポジトリ minimum-journey-bga の仕様書 006 §1.1 B9、§7 による。本リポジトリでの再確認は 009 で行う） | Game.php のページ、minimum-journey-bga `docs/specs/006-state-machine.md` |

姉妹リポジトリ minimum-journey-bga の `docs/specs/006-state-machine.md` §4（準備フェイズの同時・秘密選択）が本ゲームの同時選択の実装例になる。本書はその案 B（選んだ人を `setPlayerNonMultiactive` で非アクティブにし、変更アクションだけ `#[CheckAction(false)]` と `checkPossibleAction()` で許可する）を前提に UI を設計する。案 B が Studio で動かない場合は案 A（全員アクティブのまま、全員の選択が埋まったらサーバーが遷移）に切り替える。**どちらの案でも、本書の UI の仕様は変わらない**ように書く（UI は「確定済み」「変更」の 2 つの状態だけを前提にする）。

**組み込みの Undo は使わない（提案）。** 理由: (1) 同時選択（複数アクティブ状態）では使えない（B3）。(2) 山札のドローなど他プレイヤーに公開された情報が巻き戻ると、非公開情報が漏れうる。(3) 保存点が 1 つだけで、「いつでもできる売却」「同時処理」と相性が悪い。代わりに、同時選択は「全員が確定するまで選び直せる」（Q-09）で、複数ステップの入力はクライアント状態で集めて最後に 1 回だけサーバーへ送る（B4）。`db_undo_support` は `false`。

### 2. 共通方針

#### 2-1. 同時選択の枠組み（確定、Q-09・Q-10・Q-16・Q-17）

次の操作はすべて**同じ枠組み**で行う。

1. 状態に入ると、その操作を行う全員がアクティブになる（誰を含めるかは各操作の節）。
2. 各プレイヤーは自分の画面で選ぶ（他プレイヤーには内容が見えない）。
3. [Confirm] で**確定**する。確定すると、そのプレイヤーは非アクティブ（待機中）になり、BGA の標準表示で「待機中のプレイヤー」から外れ、持ち時間が止まる。
4. 確定後も、**最後の 1 人が確定するまでは選び直せる**（§2-2）。
5. 最後の 1 人が確定した瞬間に**全員の選択が確定**し、一斉に公開して処理する。
6. 公開後は取り消せない。

全員同時に処理するので、順番に回ってくるプレイヤーの待ち時間はない。サーバーは確定済みの選択を永続データ（DB）に保存し、状態の遷移は常にその永続データを正として判定する（姉妹リポジトリ 006 §4.4）。

#### 2-2. 確定・変更・取り消し

| 状況 | 画面 | 動作 |
| --- | --- | --- |
| 選択中（未確定） | ステータスバー: 選んだ内容の要約と [Confirm]（緑）、[Reset]（選択をクリア、灰）。必要なら [Pass] | 多段の入力（カード → 衛星 → 向き）はクライアント状態で集める（B4）。サーバーへは [Confirm] を押したときに 1 回だけ送る |
| 確定済み・他の人を待っている | ステータスバー: 「Waiting for X, Y…」。自分の確定内容の要約と [Change my choice] | 他プレイヤーには「確定済み」の印（チェックマーク）だけが見える。内容は見えない |
| [Change my choice] を押した | 選択中の画面に戻る。確定済みの内容が初期選択として入っている | 新しい内容で [Confirm] を押すと上書きする。押さずに放置しても、前の確定内容が有効なまま |
| 最後の 1 人が確定した | 全員の選択が公開され、処理に進む | 公開と同時に変更はできなくなる。直前に送った変更要求は状態不一致で拒否される（§2-8） |

- **取り消し = 選び直し**。「何も選んでいない状態に戻す」操作は用意しない（[Pass] を選ぶ、または別の内容に上書きする）。確定を保ったまま内容だけ変えられるので、変更中に時間切れになっても前の確定内容で進む。
- 変更の履歴や回数の制限はない。他プレイヤーには変更したこと自体を見せない（変更中も「確定済み」のまま）。
- 他プレイヤーの確定状況（誰が確定済みか）は公開情報。`args` の公開部分には**選択の内容を絶対に入れない**。本人の確定内容は `_private` で本人にだけ返す。再読み込み（F5）後も `getArgs` が `_private` の確定内容を返すので、確定済みの表示と [Change my choice] が復元できる。
- 売却（§2-6）は選択とは別の操作で、取り消せない。

#### 2-3. 「確認」ボタンの方針（提案、暫定 No. 2）

誤操作の防止と操作の速さのバランスとして、次の方針にする。

- **確認ダイアログ（ポップアップ）は使わない**（B6）。全操作を [Confirm] ボタンまたは選択クリックで進め、ダイアログで止めない。
- 同時選択では「**選ぶ → ステータスバーの [Confirm]**」の 2 段階にする。確定後も他の人が確定するまで変更できるが、**最後に確定するプレイヤーには取り消す余地がない**ため、1 クリックで確定しない。
- 選択肢が 1 つしかない・ [Pass] しか選べない場合も、[Confirm] ではなく [Pass] ボタンを押す 1 クリックにする。[Pass] を選んだ内容は他の選択と同様に確定済みとなり、変更できる。
- **ゲーム設定（ユーザー設定）に「Confirm with one click」を用意する**（初期値はオフ）。オンにすると、同時選択で最後の入力（例: 向きの選択）をクリックした時点で確定する。熟練者向けの高速化。
- 即時の効果を持つ操作（売却、[Use]）は、選択（カードを選ぶ）→ 実行ボタン（[Sell 2 cards (+6 Maya)] など）の 2 段階。金額や枚数がボタンに出るので、確認ダイアログの代わりになる。
- 確認ダイアログを使うのは次の 1 つだけ（B6 の基準「まれ・取り返しがつかない・誤クリックしやすい」を満たすもの）: **[Sell] で、手札の最後の 1 枚まで全部売る**とき。それ以外では使わない。

#### 2-4. 他プレイヤーへの見え方（共通）

| 時点 | 見えるもの |
| --- | --- |
| 選択中・確定済み | 各プレイヤーの「選択中 / 確定済み」の印だけ（プレイヤーパネルのチェックマークと、BGA 標準の待機中表示）。内容は一切見えない |
| 公開（最後の 1 人の確定） | 全員の選択が一斉に画面に出る。ゲームログにも選択の結果が席順（基準プレイヤーから時計回り）で並ぶ。処理は同時に行われ、ログの順は表示上の便宜（処理の順序の意味を持たない） |

- 「確定の速さ」から選択の難しさが推測されるのは、紙の同時選択でも同じ。タイマー表示などで隠す工夫はしない。

#### 2-5. 選べない・実行できない選択肢の表示

- 実行できない選択肢（コストが払えない、条件を満たさない、すでに最大枚数など）は**非表示にせずグレーで表示**し、理由を短く添える（ツールチップとステータスバー。例: 「Not enough Maya (short 3)」「This satellite already has 4 cards」）。「なぜ選べないのか」が分からない状態を避ける。
- 例外: 横向きのアクションカード（Q-14）は「選べない状態」で常に表示する（§3-1）。
- サーバーは選択の受け付け時に必ず再検証する。クライアントの表示は補助。

#### 2-6. 売却（いつでもカードを捨てて 3 マヤ）と支払い不足の促し（確定、Q-11・U-14）

**紙での操作**: 手札のプロジェクトカードを 1 枚捨てて、いつでも 3 マヤを得る（RB p.6、p.20 i）。

**BGA での操作**:

| 項目 | 内容 |
| --- | --- |
| いつできるか | (1) **自分が行動中のとき**（同時選択中を含む）、手札から [Sell] でいつでも可能。(2) 支払いでマヤが足りないときは、不足分の売却を促す。(3) **他プレイヤーだけが行動中のときの割り込みはできない**（FAQ 行 47 との差。001 D-4）。確定済みで待機中のときにできるか → 暫定 No. 4 |
| 手順 | ステータスバーに常時 [Sell cards] を出す（行動中のみ）。押すと手札のカードが複数選択できる状態になり、ボタンが [Sell N cards (+3N Maya)] に変わる。押すと即時に売却する。売却を取りやめるときは [Cancel] |
| 売却額 | 1 枚 3 マヤが基本。売却時に増減する効果（P077「オライオンリワード」、R009 など。001 §11-1）があるときは、**サーバーが計算した 1 枚あたりの売却額**を args で渡して表示する（クライアントが計算しない） |
| 他プレイヤーへの見え方 | 捨てたカードは公開（捨て札に表向きで置く）。所持マヤと手札枚数の増減が全員に見える。ゲームログに「X sold CARD for N Maya」と出る |
| 取り消し | **不可**（捨て札は公開済みで、山札のシャッフルが絡む場合もあるため） |
| zombie / タイムアウト | 自動の売却はしない |

**支払い不足の促し**: 配備・打ち上げ・通信確立などの選択で、コストが所持マヤを超えるとき。

1. 選択肢はグレーにせず、「**売却すれば払える**」ものは通常の選択肢として表示し、コストの横に「needs N more Maya (sell K cards)」と出す。手札の売却で届かないもの（手札の売却額の合計を足しても足りない）だけをグレーにする。
2. 不足のまま選ぶと、続けて「**売却するカードを選ぶ**」画面（クライアント状態）に進む。必要な最小枚数（不足分 ÷ 売却額の切り上げ）が表示され、その枚数以上を選ぶまで [Confirm] は押せない。**配備するカード自身は選べない**。
3. 選んだ売却カードは、**選択に同梱して確定する**（暫定 No. 5）。確定した内容（売却するカード）は公開（§2-4）まで他プレイヤーに見えない。公開後、処理の最初に売却を行い、そのあとコストを払う。
4. 解決時に、同梱した売却を行っても払えなくなっていた場合（他のプレイヤーの効果で所持マヤが変わった場合）の扱い → エッジケース。
5. 同時のコスト・受け取りの判定（先駆コストなど）は、001 U-11 のとおり処理前の所持金で判定する。この画面の「払える」の判定も、処理前の所持金（と売却額）で行う。

- 自分の選択に含まれる売却予定のカードは、独立の [Sell cards] からは選べない（二重売却の防止）。逆に、独立の売却で手札が減って選択内容が成り立たなくなる場合（配備予定のカードを売ろうとした等）は、そのカードを選べない（グレー）。

#### 2-7. 状態ごとの参加者

| 操作 | 参加する（アクティブになる）プレイヤー |
| --- | --- |
| アクションプロット | 全員 |
| III / IV / II / V のメインアクション | 全員（選ばれたフェイズのみ。自分がそのアクションカードを選んでいなくても参加する。001 §7-1） |
| 各フェイズのアクション選択ボーナス | そのアクションを**自分で選んだ**プレイヤーのみ（メインアクションの公開・処理の後） |
| 効果の選択（§5） | 選択が必要な効果を持つプレイヤーのみ |
| マリガン・ドラフト | 全員 |

- 選ばれていないフェイズ、ボーナスを持つプレイヤーがいないとき、その状態は飛ばす（→ 009）。
- メインアクションを行えるプレイヤーがいない（例: 全員が打ち上げ可能な衛星を持たない）ときも、状態は飛ばさず全員が [Pass] できる（暫定 No. 1 に関連して、無駄な待ちを避けるため「何もできないプレイヤーは自動で確定済み」にしてよい。サーバーが判定し、ログに「X has no available action」と出す）。

#### 2-8. 確定前後の競合と再接続

- 最後の 1 人が確定した直後に、別のプレイヤーの変更要求がサーバーに届いた場合は、状態不一致で拒否する。拒否されたプレイヤーの画面は、公開された結果で更新される。エラーは「The choices are already locked」程度の穏当な文言で出し、赤いエラーにしない（姉妹リポジトリ 006 §4.4 と同じ方針）。
- 変更要求が先に処理された場合は、変更後の内容が有効。
- 再接続・再読み込み時は、サーバーの永続データから確定済みの内容（本人にだけ）と、確定済みの人の一覧（全員）を復元する。クライアント状態の途中入力（確定前の選択）は失われてよい。

#### 2-9. タイムアウト・zombie の共通方針（提案、暫定 No. 15）

- BGA は、持ち時間切れや離脱でプレイヤーを zombie にし、各状態の `zombie()` を呼ぶ（B8。タイムアウトから `zombie()` が呼ばれるまでの BGA 側の挙動は本書では未確認。009 で確認する）。
- 方針は「**ゲームを止めず、失敗リスク（コストの支払い、名声に不利な配置）を取らない**」。基本は [Pass]（何もしない）に相当する選択を確定し、その後 `setPlayerNonMultiactive` する。zombie の処理でゲームを早期終了させない。
- zombie のプレイヤーが確定した内容は、他の人が変更するときに影響しない（他の人の選択とは独立）。
- zombie でも**終了時の手札の自動換金**（§2-10）や名声計算は通常どおり行う。
- 個別の操作の既定動作は、各節の表の最終行と、末尾の一覧（§9-1）に示す。

#### 2-10. ゲーム終了時の手札の自動換金（確定、Q-12）

**紙での操作**: 終了時に、手札のプロジェクトカードを全て捨てて 3 マヤにしてから名声を数える（RB p.20、p.21）。

**BGA での表現**: 終了条件を満たすと、名声計算の直前に、**手札を全員分まとめて自動で 1 枚 3 マヤに換金**する（売却時に増減する効果は適用する。001 §11-1）。操作は不要で、確認もしない。

- 表示: 各プレイヤーの手札が捨て札へ移り、所持マヤが増える（アニメーションとログ「X's hand was sold for N Maya at game end」）。その後、名声の内訳の表示に進む（→ 012）。
- 他プレイヤーへの見え方: 換金するカードが公開される（終了時なので問題ない）。
- 取り消し: 不可。zombie でも同じ。
- 得点が下がることはない（001 §10）ので、選択の余地を設けない。

| カードの状態 | 紙 | BGA の表示 |

#### 3-2. 打ち上げ / 転回（III、メインアクション）

| 項目 | 内容 |
| --- | --- |
| 紙での操作 | 非稼働の衛星コマを 1 基取り、全員一斉に、(a) 自分の発射拠点の区域に向きを指定して置く（打ち上げ）か、(b) 稼働中の衛星の衛星カード上に向きを指定して置く（転回）（RB p.14、001 §7-4） |
| BGA での操作 | ステータスバーに [Launch]・[Turn]・[Pass] を出す。下記の手順 |
| 他プレイヤーへの見え方 | 確定済みの印だけ。公開時に、打ち上げは衛星コマが発射拠点の区域に**指定の向きで**現れ、転回は対象の衛星の向きが変わる（アニメーション）。[Pass] はログのみ |
| 取り消し | 全員が確定するまで可 |
| zombie / タイムアウト | [Pass]（コストを払わず、衛星を動かさない） |

**打ち上げの手順**:

1. [Launch] を押す。打ち上げられる衛星（非稼働で、プロジェクトカードが 1 枚以上配備されている。001 §7-4）が、衛星カードの一覧の中で選べる状態になる。条件を満たさない衛星はグレーで、理由を添える（「No Project cards deployed」）。コストが払えない衛星は、「needs N more Maya」と表示し、売却で払えるなら選べる（§2-6）。
2. 衛星を 1 つ選ぶ（クリック）。**打ち上げコスト（効果による増減を反映した値）**と、打ち上げ後の所持マヤがステータスバーに出る。
3. 盤面の**自分の発射拠点の区域**の上に、半透明の衛星コマ（プレビュー）が現れ、**6 方向の矢印（NE / E / SE / SW / W / NW）**が周囲に出る。発射拠点の区域は 1 つなので、区域の選択はない。
4. 向きの矢印をクリックする。プレビューの衛星コマが選んだ向きに回転する。矢印は何度でも選び直せる。
5. [Confirm] で確定する。

- 向きは 6 方向すべて（003 §4.1、作者回答 2026-10-20）。「右上・右・右下・左下・左・左上」。矢印のラベルはカーソルを重ねたときに出す（「Up-right」「Right」など。英語の UI 文言は案）。
- 発射拠点にすでに自分の別の衛星がいても打ち上げられる（重なる。001 §7-4）。プレビューは通常の衛星コマと重ねて表示する。
- プレビューは**本人の画面だけ**に出す。他のプレイヤーには出さない。

**転回の手順**:

1. [Turn] を押す。稼働中の自分の衛星が盤面上で選べる状態になる（衛星コマ、または衛星カードのパネル上でクリック）。
2. 対象の稼働中の衛星を 1 つ選ぶ。その衛星の現在の向きが矢印で表示される。
3. 6 方向の矢印から新しい向きを選ぶ。**現在の向きと同じ向きも選べる**（向きを変えない 360° 転回。FAQ 行 17）。その場合は矢印に「(same direction)」と表示し、転回の効果が発動することをツールチップに書く。
4. [Confirm] で確定する。

- 紙では「非稼働の衛星コマを 1 基取って稼働中の衛星カードの上に置き、処理後に戻す」（FAQ 行 40）。BGA では、**置く非稼働のコマの選択は省略する**（どの衛星コマでも結果は同じで、処理後に戻るため）。ただし**非稼働の衛星が 1 機もいない**（5 機すべて稼働中）ときは転回できない（紙では置くコマがないため。001 §7-4）。その場合 [Turn] はグレーにして「No inactive satellite to place」と出す（暫定 No. 6）。
- 転回にコストはない（001 §7-4）。
- 反射は転回ではない（001 §9-1）。ここでは扱わない。

#### 3-3. 打ち上げ / 転回のアクション選択ボーナスと同時選択

| 項目 | 内容 |
| --- | --- |
| 紙での操作 | III を選んだプレイヤーのみが、メインの処理の後に、非稼働の衛星コマを 1 つ取り、全員一斉に**衛星カードの上に**任意の向きで置く。稼働中の衛星カードの上 = 転回、非稼働の衛星カードの上 = 予算上昇（予算 +1）（RB p.14、p.15 例 3・例 4） |
| BGA での操作 | ステータスバーに [Turn]・[Budget +1]・[Pass] を出す。[Turn] の手順はメインの転回と同じ。[Budget +1] は選ぶだけ（対象や向きの入力はない）。[Confirm] で確定する |
| 他プレイヤーへの見え方 | 確定済みの印だけ。公開時に、転回は衛星の向きが変わり、予算上昇は予算トラックの円盤（予算の数値）が +1 になる |
| 取り消し | 全員が確定するまで可 |
| zombie / タイムアウト | [Pass] |

- ボーナスでは打ち上げは選べない（001 §7-4）。ボタンも出さない。
- 複数のプレイヤーがボーナスを得るとき（RB p.15 例 3）は、メインと同じ同時選択（§2-1）。
- **予算上昇の前提**: 紙では非稼働の衛星カードの上に非稼働のコマを置く。BGA では対象の選択を省略し、「非稼働の衛星が 1 機以上いること」を条件にする（暫定 No. 6）。
- 「ボーナスアクションの前に、メインアクションの結果（打ち上げ時の効果など）がすべて処理される」順序は 007 で決める。

#### 3-4. 通信確立（IV、メインアクション）

| 項目 | 内容 |
| --- | --- |
| 紙での操作 | 自分のキューブを 1 つ取り、全員一斉に「通信確立可能区域」の上、またはゲームボード外に置く。ボード外 = 通信確立アクションの放棄（RB p.16、001 §7-5） |
| BGA での操作 | 盤面の通信確立可能区域が**ハイライト**される。区域をクリックして選び、必要なら衛星を選び、[Confirm]。**ボード外に置く操作の代わりに [Pass] ボタンを押す**（確定、Q-10。ボタン名は [Pass] とし、補足として「(abandon the cube)」を添える） |
| 他プレイヤーへの見え方 | 確定済みの印だけ。公開時に、キューブが選ばれた区域に現れ（Z の順のキューブ置き場。003）、コストが支払われる。[Pass] は盤面に何も出ない（ログに「X passed the link action」）。放棄したキューブは使用済みにならず、通信確立数に数えない（001 §10） |
| 取り消し | 全員が確定するまで可 |
| zombie / タイムアウト | [Pass]（キューブを放棄。コストを払わない） |

**手順**:

1. 状態に入ると、通信確立可能区域（001 §7-5 の条件 (i)(ii)(iii)）のうち、**払える区域**が通常のハイライト、**売却すれば払える区域**が点線のハイライト（クリック可能）、**払えない区域**はハイライトなし（クリックしても「Not enough Maya」）になる。
2. 区域にカーソルを重ねる（モバイルでは区域をタップ）と、**コストの内訳**を事前表示する。

   ```text
   Link cost: Area 5 + Pioneer 3 (to Blue) = 8 Maya
   You will have 4 Maya left.   (+ sells 2 cards if needed)
   ```

   内訳は「区域コスト」「先駆コスト（誰に払うか）」「カード効果による増減」「通信確立後の所持マヤ」。サーバーが計算した値を args で渡す（クライアントでは計算しない）。**他のプレイヤーが同じ区域を同時に選ぶ場合は先駆コストが発生しない**（001 §7-5）が、他人の選択は見えないので、**事前表示は「すでに置かれているキューブに対する先駆コスト」だけ**（最悪値）にする。公開後に実際の支払いが少なくなることがある旨を、コスト表示の注記（「If another player links this area at the same time, no Pioneer cost is paid between you」）に書く。
3. 区域を 1 つクリックして選ぶ。選択中の区域は枠が光り、キューブのプレビュー（半透明）がキューブ置き場に出る（本人の画面だけ）。
4. **その区域を通信確立できる自分の衛星が複数いる場合**（001 §7-5: 「どの衛星が通信確立したかを自由に選べる」）は、続けて**衛星の選択**に進む。候補の衛星が区域の上に並んで表示され（衛星の形状と向き、燃料の残量も表示。§7）、クリックして選ぶ。候補が 1 機だけなら、この手順は出ない。効果（深海の燃料回復、「通信確立したとき」の効果）の対象になるので、選択を省略しない。
5. [Confirm] で確定する。

- 衛星から区域を選ぶ入口も用意する: 先に自分の衛星をクリックすると、その衛星が通信確立できる区域だけがハイライトされる。**どちらから入っても、結果は「区域 + 衛星」の組**。
- 通信確立コストが 0 になるときは「Free」と表示する。
- 電波遮断装置など、通信確立できない衛星を作るカード（001 §7-5、FAQ 行 56）がある衛星は、候補から外す。
- 他のプレイヤーの発射拠点がある区域も選べる（持ち主に先駆コスト 3 を払う。U-10）。

#### 3-5. 通信確立のアクション選択ボーナス

| 項目 | 内容 |
| --- | --- |
| 紙での操作 | IV を選んだプレイヤーのみが、メインの処理の後に、同じく全員一斉にキューブを置く（または放棄する）。対象区域は、自分の衛星の直下に加え、**進行方向の前後に隣接する区域**（RB p.16、p.5） |
| BGA での操作 | §3-4 と同じ。ハイライトされる区域が、衛星の直下 + 前後の隣接区域になる。衛星の選択は、区域ごとに「その区域に届く衛星」が複数のときだけ出る |
| 他プレイヤーへの見え方・取り消し・zombie | §3-4 と同じ |

- ボーナスの対象区域は、通信確立できる衛星の向き（進行方向）を矢印で表示して分かりやすくする。前方は反射を考慮しない（003 §4、RB p.17 例 5・例 6）。
- メインアクションの通信確立で置いたキューブが盤面に出た後にボーナスを行う（先駆コストが発生する。001 §7-5）。コストの事前表示は、メインの結果が盤面に反映された後の状態で計算する。
- **特殊通信確立**（カード効果で「特殊通信確立コストを支払ってもよい」とされたとき。001 §7-5）は、効果の選択（§5）の 1 つとして扱う。[Use special link (cost N)] / [Skip] を聞き、コストの内訳を事前表示する。

#### 3-6. 配備（II）

| 項目 | 内容 |
| --- | --- |
| 紙での操作 | 手札のプロジェクトカードを 1 枚選び、配備コスト（稼働中の衛星なら +5）を払い、好きな衛星に配備する（カードを衛星カードの上に重ねる）（RB p.13、001 §7-3） |
| BGA での操作 | (1) 手札のカードをクリックして選ぶ。(2) 配備先の衛星を選ぶ（衛星カードのパネルをクリック）。(3) [Confirm]。何も配備しないときは [Pass]。選ぶ順は「カード → 衛星」。衛星を先に選ぶ入口も用意する（衛星をクリックすると手札のカードが選べる状態になる）。**どちらから入っても結果は「カード + 衛星」の組**。ボーナス保持者は、この選択に続けて §3-7 の追加の行動も選ぶ（同じ [Confirm] で確定） |
| 他プレイヤーへの見え方 | 確定済みの印だけ（手札のカードは非公開）。公開時に、配備されたカードが衛星に**重なる**アニメーションとログが出る。配備時効果は 007 の処理順に従う |
| 取り消し | 全員が確定するまで可 |
| zombie / タイムアウト | [Pass] |

**コスト表示と選べない理由（§2-5、§2-6）**:

- 手札のカードにカーソルを重ねる（モバイルではタップ）と、**そのカードを選んだ場合のコスト**を衛星ごとに表示する。「Cost 5 (+5 active satellite) = 10」のように、基本コスト、稼働中の追加 +5、効果による増減、合計を出す。
- 衛星の側にも、現在選んでいるカードのコストを出す（稼働中の衛星は +5 を含めた値）。
- **すでに 4 枚配備されている衛星**はグレー（「This satellite already has 4 cards」）。
- 配備後の燃料庫の数（容量 C）の変化と、重なる位置（一番上）を、プレビューで示す（§7）。
- 配備を禁じるカード効果（P033 など。002 §エッジケース）の衛星は、グレーにして理由を出す。
- 手札が 0 枚のときは [Pass] のみ（自動で確定済みにしてよい。§2-7）。

#### 3-7. 配備のアクション選択ボーナス

**通常の配備（§3-6）と同時に行う**（作者回答 2026-10-20。「配備の追加アクションは、通常の配備と同時に行う」）。別の選択状態は設けず、状態 61 の 1 回の選択で、通常の配備に加えて追加の配備または 1 枚引くを選ぶ。全員の確定後に全員分を一斉に処理する。

| 項目 | 内容 |
| --- | --- |
| 紙での操作 | II を選んだプレイヤーのみ、(i) 追加で 1 枚配備するか、(ii) プロジェクトカードを 1 枚引く（RB p.13、A002 BONUS） |
| BGA での操作 | 1 枚目（§3-6）のカードと衛星を選ぶと、ステータスバーに [Deploy another card]・[Draw 1 card] が出る（ボーナス保持者だけ。セットアップの配備フェイズは全員）。[Deploy another card] は §3-6 と同じ操作でもう 1 組を選ぶ（同じ衛星でもよい。選び終えるまで 1 枚目は固定で、[Do not deploy another card] で 1 枚目の選び直しに戻れる）。[Draw 1 card] は選ぶだけ（[Do not draw] で取り消せる。通常の配備なしで引くだけも可）。コストの内訳は 2 枚分と合計を出し、起動の修正は 1 枚ごとに選ぶ（同じ起動は 1 枚にだけ）。支払い不足は**合計に対して**売却を促す（配備する 2 枚は売れない）。[Confirm] で 1 回に確定。[Pass] は通常の配備もボーナスも行わない |
| 他プレイヤーへの見え方 | 確定済みの印だけ。公開時に、配備はカードが衛星に重なり、ドローは山札から手札へカードが移る（他のプレイヤーには**カードの裏面**が手札へ移るだけ） |
| 取り消し | 全員が確定するまで可 |
| zombie / タイムアウト | [Pass]（配備もドローもしない。山札を減らす選択も避ける） |

- 引いたカードは、公開時に山札から引く（確定時ではない）。確定前にめくって見ることはない（§6）。同時処理なので、引いたカードは同じ選択の配備には使えない（追加の配備に選べるのは、選んだ時点で手札にあるカードだけ）。
- 追加の配備が通常の配備と同じ衛星のとき、1 機 4 枚の上限は 2 枚を合わせて数える（満杯になる衛星はグレーにして理由を出す）。稼働中の衛星への +5 は 1 枚ごと。
- 公開時の処理の順: 売却（合計に対して 1 回）→ コストの支払い → 通常の配備 → 追加の配備 → 1 枚引く。配備時の効果は 2 枚分を全員分まとめて同時に処理する（007、Q-17 と同じ窓）。

#### 3-8. 企画（V）

| 項目 | 内容 |
| --- | --- |
| 紙での操作 | メイン: プロジェクトカードを 2 枚引き、1 枚を手札に残し、1 枚を捨てる。ボーナス（V を選んだプレイヤー）: 上記の代わりに 5 枚引き、2 枚を残し、3 枚を捨てる（RB p.15） |
| BGA での操作 | 状態に入ると、サーバーが**各プレイヤーにカードを引かせて**（引く枚数はメインなら 2、V を選んだプレイヤーは 5。効果による増減を含む）、本人にだけ表向きで見せる。残すカードをクリックして選ぶ（メイン: 1 枚、ボーナス: 2 枚）。[Confirm] で確定する。残りのカードは捨てる |
| 他プレイヤーへの見え方 | 確定済みの印だけ。公開時に、**捨てた枚数**とカード（捨て札は公開）、手札が増えた枚数が見える。引いたカードのうち残したものは非公開のまま |
| 取り消し | 全員が確定するまで、残すカードの選び直しは可。**引いたカード自体は取り消せない**（山札から引いた時点で確定。選び直しでも別のカードを引き直すことはない） |
| zombie / タイムアウト | **引いた順の先頭から**必要な枚数を残し、残りを捨てる（山札の公開順序に依存せず、ゲームを止めない） |

- V のメインとボーナスは別の処理で、V を選んだプレイヤーはボーナス（5 枚引いて 2 枚残す）が「メインの代わり」になる（001 §7-6）。画面にはどちらを行うか（Draw 5, keep 2）を明示する。
- 山札が足りないときの扱い（捨て札のシャッフルなど）は 001 §2-1 のとおり。
- **引くタイミングの注意**: 全員同時にカードを引くので、山札からの配り順を決める必要がある。**基準プレイヤーから時計回りの席順で配る**（山札の順序の決定のためだけで、処理の順序の意味を持たない）。

#### 3-9. 予算発行（I）

- メイン（予算の値だけ +マヤ）とボーナス（+6 マヤ）は選択がないので、**操作は不要**（自動処理）。公開後のアニメーション（マヤが増える）とログだけ。
- 予算発行フェイズの始めに発動する効果（P006 など）が選択を要する場合は §5。

### 4. 起動効果の使用と使用済みマーク（確定、Q-13）

**紙での操作**: 効果を使ったカードを少し傾けて、今ラウンドは使用済みであることを示す（RB p.6）。

**BGA での表現（確定）**: カードを傾けず、**使用済みマーク**で示す。

| 状態 | カードの表示 |
| --- | --- |
| 起動効果あり・今ラウンド未使用 | 歯車アイコン（カードの効果タイプの歯車と同じ。使用可能であることを示す） |
| 使用済み | **歯車に × を重ねたアイコン**。カードを少し暗くする |
| 起動効果でない（常時など） | マークなし |

- 歯車アイコンはカード画像の効果タイプ欄にすでに印刷されている（002 §3.4）。使用済みマークは、そのカードの**上に重ねる表示**（画像を差し替えない。→ 012）。
- 稼働中のみ発動する効果（◎）を持つカードが、非稼働の衛星に配備されている間は、歯車を通常より薄く表示して「発動できない」ことを示す（ツールチップ: 「Active satellites only」）。
- **ラウンドの終わりに、全てのカードの使用済みを自動で戻す**（Q-13）。戻すタイミングは、終了判定の後・次の計画フェイズの前（計画フェイズ中に発動する起動効果 P001〜P003 がある。007 と合わせる。暫定 No. 7）。戻すときは × が消えるアニメーションを出す。
- 他プレイヤーのカードの使用済みマークも、全員に公開される（紙でも誰からも見える）。

**[Use] / [Skip]（確定、Q-13）**:

| 項目 | 内容 |
| --- | --- |
| 紙での操作 | 条件を満たしたとき、任意で効果を使う（使うならカードを傾ける） |
| BGA での操作 | 任意の起動効果は、**条件を満たした時点**で、そのカードを持つプレイヤーに [Use] / [Skip] を聞く。ステータスバーに [Use CARD_NAME] と [Skip] を出し、該当のカードを盤面上でハイライトする。[Use] を選んで選択が必要な効果（対象を選ぶなど）は、続けて §5 のとおり選ぶ。**強制の効果は自動で処理**し、聞かない（ログに出す） |
| 他プレイヤーへの見え方 | 聞いている間は「X is deciding on CARD_NAME」と待機中の表示（効果を持つカードは公開情報）。[Use] を選ぶと使用済みマークが付き、効果の結果が公開される。[Skip] はログだけ（「X skipped CARD_NAME」） |
| 取り消し | 効果の選択（§5）と同じ。確定したら取り消せない（No. 3、009 未確定 1 で変更、2026-10-19） |
| zombie / タイムアウト | [Skip] |

- 同じタイミングで複数の起動効果が使えるときは、1 つの画面に**候補のカードを全部並べ**、それぞれに [Use] / [Skip] を付ける（1 つずつ聞かない。速さを優先する）。
- [Skip] した効果が**使用済みになるか**、同じラウンド内で条件を再び満たしたときに再び聞くか → 暫定 No. 8。暫定案: [Skip] は使用済みにしない。再び条件を満たしたら聞く。聞く回数が多すぎるときの救済として、[Skip for this round]（そのカードは今ラウンド聞かない。ラウンドの終わりに戻る）を併設する。

### 5. 効果の選択が全員同時に発生するときの UI と、自分の効果の順番

#### 5-1. 全員同時の効果の選択（確定、Q-16・Q-17）

**紙での操作**: 複数のプレイヤーの効果が同じタイミングで発動するときは、基準プレイヤーから時計回りに順番に処理する（RB p.18、p.20）。

**BGA での表現（確定）**: **順番に処理せず、全員が同時に選び、全員が終わってから一斉に結果を反映する**（Q-16）。セットアップ手順 16 の配備時効果も同じ（Q-17）。

| 項目 | 内容 |
| --- | --- |
| BGA での操作 | 選択が必要な効果を持つプレイヤー全員に、効果の画面を同時に出す。画面には、(1) 効果のカード（名前と効果文）、(2) 選択肢（カード・衛星・区域・[Yes] / [No] など。効果ごと → 011）、(3) [Confirm] を出す。選択が要らないプレイヤーは参加しない（自動で処理する）。全員が [Confirm] したら、結果を一斉に反映する |
| 他プレイヤーへの見え方 | 待機中の表示で「Waiting for X (CARD_NAME)」と出す。**効果のカード名は公開情報**（盤面上のカードから分かる）で、**選択の内容は結果の反映まで非公開**。選択の途中経過は見せない。反映時に、全員の効果の結果が一斉にアニメーションする |
| 取り消し | 不可。確定した時点で解決される（No. 3、009 未確定 1 で変更、2026-10-19。引き直しを防ぐため） |
| zombie / タイムアウト | その効果の「**何もしない / 辞退**」を確定する。辞退がない強制の効果は、**もっとも不利が少ない既定の選択**（候補の先頭など）を効果ごとに 011 で決める。ここでは枠組みだけを決める |

- 山札を見て選ぶ効果（例: 山札の上のカードを見て並べ替える）で、見たカードの内容は**本人にだけ**見せる。選びなおしても山札の内容は変わらないので、変更を許しても情報は漏れない（確定は結果の反映時）。
- 選んだ結果が他のプレイヤーの選択に影響する効果（まれ）の扱いは 007。ここでは、全員の選択は互いに独立して行い、影響は反映時に処理する前提とする。
- 1 人のプレイヤーが複数の効果の選択を持つときは、1 つの画面に全部載せる（§5-2）。

#### 5-2. 自分の効果の順番を選ぶ UI（確定、Q-15）

**紙での操作**: 1 人のプレイヤーに同じタイミングの効果が複数あるとき（例: 1 機の衛星の打ち上げ時効果が 3 枚）、処理する順番を自分で決める。

**BGA での表現（確定、Q-15）**:

- **順番によって結果が変わりうる場合**（007 で、結果が変わるかを判定する）だけ、そのプレイヤーが順番を選ぶ。結果が変わらない場合は、**衛星カード → 下に配備したカードから順**に自動で処理する（確定、Q-15）。順番の選択を聞かない。
- 順番を選ぶ UI: 効果のカードを**縦のリスト**で並べ、各行に番号（1, 2, 3…）を振る。**初期の並びは自動処理の順**（衛星カード → 下に配備したカード）。カードをクリックして並べ替える（先頭へ・1 つ上へ・1 つ下へ）か、ドラッグして並べ替える。[Confirm order] で確定する。モバイルではクリックによる並べ替えを基本にし、ドラッグは補助。
- この画面は、§5-1 の効果の選択の画面の**前段**として、同じ状態の中で表示する（全員同時）。順番を選ぶ人と、選択だけの人が混在しても、全員が同時に進む。
- 他プレイヤーへの見え方・取り消し・zombie: 順番は他プレイヤーには結果の反映まで見えない。確定後は変更できない（No. 3）。zombie / タイムアウトは**初期の並び（自動処理の順）**を確定する。
- 複数の効果の順番が「結果が変わるか」の判定、1 回の処理の中での順番の適用は → 007。

### 6. 非公開情報の見え方

| --- | --- | --- | --- |

- 配備したカードは公開情報（衛星の上に重ねられる）。他プレイヤーは衛星のパネルで配備されたカードの内容を確認できる（→ 012）。

### 7. 燃料の表示

**紙での操作**: 衛星カードとプロジェクトカードの燃料庫を縦につなぎ、燃料コマを 1 つずつ上へずらして燃料の消費を表す。燃料回復は下へ戻す（RB p.6〜7、p.19、001 §4-4）。

**BGA での表現（提案、暫定 No. 9）**: 衛星ごとに、**ゲージ（燃料庫の並び）と数値**の両方を表示する。

- **ゲージ**: 衛星カードの燃料庫 + 配備されているカードの燃料庫を、下から上へ縦に（または横に）並べた**スロットの列**として描く。紙と同じ向き（初期燃料庫が一番下）。燃料コマは**現在の位置のスロット**に表示する。**消費した燃料 c の数だけ**初期燃料庫から上に進む。配備でカードが重なると、スロットが増える（容量 C の増加）。
- **数値**: ゲージの横に「**Fuel R / C**」（残量 / 容量。R = C − c）を出す。例: 容量 8、消費 3 なら「Fuel 5 / 8」。
- **燃料切れ（c > C）**: ゲージの最上段の**さらに上**に、「Out of fuel」の枠と燃料コマを置く。数値は「Fuel 0 / C」ではなく「**Out of fuel**」と出し、赤く表示する。**着陸 / 着水は循環フェイズの判定のときだけ**で、燃料切れの表示になっても、その時点では着陸しない（001 §4-4）。ツールチップに「Will land at the next landing check.」と出す。
- **残量が 1 以下**（ニアミスで燃料切れになる可能性が高い）のとき、数値を黄色にする（任意の強調。実装の優先度は低い）。
- 燃料の消費・回復は、コマが 1 スロットずつ動くアニメーション（1 つの変化につき 0.3 秒程度）で見せる。消費・回復の理由（移動・ニアミス・区域ボーナス・効果）はゲームログに書く。
- **表示する場所**: (1) 衛星カードのパネル（常に）、(2) 盤面上の衛星コマにカーソルを重ねたとき（ツールチップで「Fuel R / C」）、(3) 通信確立の衛星の選択（§3-4）と配備先の選択（§3-6）の候補。
- 非稼働の衛星は、燃料コマが初期燃料庫にあり、「Fuel C / C」（満タン）で表示する。打ち上げ後も満タンから始まる（001 §7-4、FAQ 行 39）。
- 配備によって燃料庫が増えたとき、燃料切れ（c > C）の衛星は燃料切れのままで、ゲージの燃料コマは外に出たまま（001 §4-4、U-6）。
- 燃料の数値は公開情報（全員が見える）。

### 8. マリガン・ドラフト（ゲームオプション）

001 §3-5 のゲームオプション。ドラフトの実装は後回し（確定、Q-06）。マリガンはドラフトなしのときの追加オプション（作者の追加、Q-06、U-4）。

#### 8-1. マリガン

| 項目 | 内容 |
| --- | --- |
| 紙での操作 | 初期の手札 5 枚を、1 回だけ好きな枚数を捨てて、同じ枚数を山札から引き直す |
| BGA での操作 | 全員が同時に行う（001 §3-5）。手札の 5 枚から、捨てるカードをクリックで複数選択（トグル）し、[Mulligan N cards] で確定する。1 枚も捨てないときは [Keep all]。確定後は、他の人が確定するまで選び直せる（§2-2） |
| 他プレイヤーへの見え方 | 確定済みの印だけ。全員が確定したら、**捨てたカードを公開して**捨て札に置き、同じ枚数を山札から引き直す（引いたカードは本人にだけ見える。捨てたカードは山札に戻さない。U-4） |
| 取り消し | 全員が確定するまで可。1 回だけ（引き直したカードをさらにマリガンすることはない） |
| zombie / タイムアウト | [Keep all] |

- 引き直しのカードは、**基準プレイヤーから時計回りの席順で山札から配る**（山札の順序の決定のため）。
- マリガンの位置づけはセットアップ手順 14 と 15 の間（手札を配った直後）。

#### 8-2. ドラフト（後回し）

| 項目 | 内容 |
| --- | --- |
| 紙での操作 | 配られた 5 枚から全員が秘密裏に 1 枚選び、残りを左隣に回す。次に渡された 4 枚から 1 枚選んで残りを左隣に回す。これを繰り返し、各プレイヤーが 1 枚ずつ選んで合計 5 枚が手札になる（RB p.28、001 §3-5） |
| BGA での操作 | 全員が同時に、**自分の前にあるパック**（最初は自分の 5 枚、以降は右隣から回ってきた残り）から 1 枚をクリックして選び、[Confirm] で確定する。全員が確定したら、**選んだカードが手札に入り、残りのパックを左隣に渡す**。これを 5 回行う。最後（1 枚だけのパック）は自動で手札に入る |
| 他プレイヤーへの見え方 | 確定済みの印だけ。選んだカードもパックの中身も非公開。「左隣」は BGA の席順の次のプレイヤー（時計回り。001 §2-2 の基準プレイヤーの席順と合わせる） |
| 取り消し | その回の全員が確定するまで可。確定の後、パックを渡した後は不可 |
| zombie / タイムアウト | パックの**先頭のカード**を選んで確定する（毎回同じ規則で、ゲームを止めない） |

- 全員が足並みをそろえて進める方式（各回の全員確定を待つ）を暫定案とする。早く選んだ人が先へ進める非同期方式（パックが届いた人から進む）は、待ち時間を減らせるが、状態の設計が複雑になる（→ 009）。暫定 No. 11。
- ドラフトとマリガンは同時には選べない（ゲームオプションは排他。001 §3-5）。

### 9. 後続への申し送り

#### 9-1. 各操作の zombie / タイムアウトの既定動作の一覧

| 操作 | 既定の動作 | 理由 |
| --- | --- | --- |
| アクションプロット | I 予算発行を確定 | 常に選べる。コストなし |
| 打ち上げ / 転回（メイン・ボーナス） | [Pass] | コストを払わない |
| 通信確立（メイン・ボーナス） | [Pass]（キューブを放棄） | コストを払わない。放棄したキューブは使用済みにならない |
| 配備（メイン・ボーナス） | [Pass] | コストを払わない。ドローもしない |
| 企画 | 引いた順の先頭から残す | ゲームを止めない |
| 売却 | 自動の売却はしない | 手札を失わない |
| 起動効果の [Use] / [Skip] | [Skip] | 強制ではない |
| 効果の選択 | 辞退（なければ効果ごとの既定。→ 011） | 不利が少ない |
| 効果の順番 | 初期の並び（自動処理の順） | 結果が変わらない場合と同じ |
| マリガン | [Keep all] | 失敗リスクを避ける |
| ドラフト | パックの先頭 | 規則が固定 |

- zombie になったプレイヤーの手番でも、自動処理（終了時の換金、名声計算）は通常どおり行う。
- zombie の処理の後は、必ず `setPlayerNonMultiactive`（または案 A の確定の記録）を行い、他のプレイヤーをブロックしない。

## 受け入れ条件

- [ ] 同時選択（プロット、III・IV・II・V のメインとボーナス、効果の選択、マリガン、ドラフト）が、選ぶ → [Confirm] → 全員の確定で一斉公開の流れで動く（§2-1）
- [ ] 確定済みのプレイヤーが、最後の 1 人が確定するまで [Change my choice] で選び直せる。最後の確定の後は変更が拒否され、穏当な文言になる（§2-2、§2-8）
- [ ] 他プレイヤーには、確定済みの印だけが見え、選択の内容は公開まで見えない（サーバーが `_private` と通知で制御する）（§2-4、§6）
- [ ] アクションカード 5 枚が常に表示され、前ラウンドに選んだ I 以外が横向き・グレーアウトで選べない。回収は自動（§3-1）
- [ ] 打ち上げは発射拠点で向きを選び、転回は対象の稼働中の衛星と向きを選ぶ（現在と同じ向きも可）。ボーナスは [Turn] / [Budget +1] / [Pass]（§3-2、§3-3）
- [ ] 通信確立は、区域の選択（または衛星からの選択）、複数衛星のときの衛星の選択、コストの内訳の事前表示、[Pass] による放棄ができる（§3-4、§3-5）
- [ ] 配備はカードと衛星の選択とコスト表示（稼働中は +5）、4 枚の上限のグレー表示ができる。企画は引いたカードから残すカードを選べる（§3-6、§3-8）
- [ ] [Sell] が行動中にいつでもでき、支払い不足のときに売却を促す。他プレイヤーだけが行動中のときは売却できない。ゲーム終了時の手札は自動で換金される（§2-6、§2-10）
- [ ] 起動効果は歯車 → 歯車 + ×のマークで表示され、ラウンドの終わりに戻る。[Use] / [Skip] が条件を満たした時点で聞かれる（§4）
- [ ] 複数のプレイヤーの効果の選択が同時に出て、全員が終わってから一斉に反映される。同じプレイヤーの複数の効果の順番を、結果が変わりうるときだけ選べる（§5）
- [ ] 手札・ミッションカード・伏せたアクションが他プレイヤーに見えない（§6）
- [ ] 燃料がゲージと「Fuel R / C」で表示され、燃料切れは「Out of fuel」と表示される（§7）
- [ ] マリガン（全員同時、1 回）が動く。ドラフトは後回しだが、仕様のとおりに実装できる（§8）
