## 目的

BGA 版 PROJECT EDGEWORTH の**画面レイアウト（PC とスマートフォン）**、**横長の六角形の盤面の描画**、**カード・コマの表示**、**プレイヤーパネル**、**画像のスプライト化と容量の上限**、**多言語対応**、**BGA のメタ画像**を決める。実装者がこの仕様書だけで、生成スクリプトと画面の骨組みを作れる具体性を目標にする。

## スコープ

- 対象: 画面領域の配置（PC・スマホ）、盤面の描画方式と幾何、区域ハイライトと操作の見た目、衛星カードと配備カードの表示、燃料ゲージ、起動効果の使用済みマーク、拡大表示、プレイヤーパネル、フェイズ帯、スプライトの構成と生成方法、容量の上限、多言語、メタ画像の規格と原本の候補、スマホ対応の注意点
- 対象外: スクリプト・画像・CSS・JS の作成（本タスクはコードを書かない。`data/` も変更しない）、状態遷移（009）、DB・通知の詳細（010）、各カード効果の選択 UI の中身（011）、ルールそのもの（001）、CI・同期ワークフロー本体（005、T-006）。ただしアセット検査の値と生成物のパターンはここで決める（005 §2.9 の申し送り）

### 2. 画面レイアウト

#### 2.1 BGA の制約

- **【確認】**（Mobile）`gameinfos.jsonc` の `game_interface_width.min`（既定 740）は「実際に動く幅」を宣言する。`autoscale: true`（既定）は CSS zoom でゲーム領域を縮めるだけで、「狭い画面向けにレイアウトを直すことの代わりにはならない」。モバイルではプレイヤーパネルがゲーム領域の**上**へ移動し、`#ebd-body` に `mobile_version` が付く。タッチ端末には `touch-device`、そうでなければ `notouch-device` が付く。ホバー用のスタイルは `.notouch-device` を前置する。必須の情報をホバーだけに置かない。
- **【確認】**（GameJs）ツールチップ（`addTooltip`）は「モバイルでは信頼できない」と明記されている。**必要な情報は、タップで開く拡大表示にも必ず出す**。
- 004 の確定事項: `game_interface_width.min = 740`（暫定）、`player_colors` は初期のまま。本仕様書で次のとおり**見直しを提案する**（未確定事項 No.1、No.2）。

#### 2.2 方針

- **盤面だけが横長**（12.5 区域幅）で、他の領域は折り返せる。盤面は専用のスクロール／拡縮コンテナに入れ、それ以外の領域は CSS の折り返しだけで PC とスマホを両立する（HTML は 1 系統。姉妹の案 B と同じ考え方）。
- **レイアウトの切り替えは `@media` ではなく、ゲーム領域の実際の幅**で行う。`ResizeObserver` で `#pe-root` の幅を測り、`data-layout="wide | medium | narrow"` と CSS 変数 `--pe-hex-w`（盤面の区域の幅、px）を JS で設定し、CSS は属性セレクタで書く。理由: BGA は右側のプレイヤーパネル・ログと CSS zoom（autoscale）のため、ビューポートの幅とゲーム領域の幅が一致しない。姉妹では `cqw` ベースの寸法がスマホ幅で崩れ、JS が入れる px 値（`--mj-bw`）に切り替えて直した（姉妹 #37）。
- 区分【提案】:

| `data-layout` | `#pe-root` の幅 | 想定 | 盤面の区域幅 `--pe-hex-w` |
| --- | --- | --- | --- |
| `wide` | 1180 px 以上 | PC（全画面） | 幅 ÷ 12.5 を 150 px で頭打ち（約 94〜150 px） |
| `medium` | 700〜1179 px | 小さい PC、タブレット横向き | 幅 ÷ 12.5（56〜94 px） |
| `narrow` | 700 px 未満 | スマホ、タブレット縦向き | 既定 52 px。ズームで 36〜96 px。盤面は横スクロール（§3.8） |

- 数値は初期値。Studio の実画面で調整してよい（姉妹の教訓: 先に PC・スマホの両方でカードと盤面だけを作って実寸を確かめる）。
- **`game_interface_width.min`**: 盤面を除く領域が 1 カラムで成立する最小幅（約 360 px）に下げ、盤面は自前でスクロールさせる案を**提案**する（現行は 740 で、スマホでは BGA が約 0.5 倍に縮小し文字が読めなくなる）。確定は Studio の実機確認の後（未確定事項 No.1）。
- bga-zoom（BgaZoom）は、**ゲーム領域全体ではなく盤面コンテナにだけ**使う案を第一候補にする（§3.8）。**【確認】** bga-zoom は CSS `zoom` で拡縮し、`element`、`zoomControls`、`localStorageZoomKey`、`autoZoom: { expectedWidth, minZoomLevel }` を持つ。BGA の autoscale も CSS zoom なので二重になり、座標は `getBoundingClientRectIgnoreZoom()`（Mobile）で読む必要がある。**使わず自前の拡縮（`--pe-hex-w` の段階変更）にする案**との比較は §3.8、未確定事項 No.3。

### 3. 盤面の描画

#### 3.1 方式（004 §9 の確定）

004 §9 の案 A（地域ボードの印刷画像を背景にし、その上に透明な六角形を重ねる）と案 C（区域タイルを並べる）を、003 の確定事項と照らして比べた。

| 観点 | 案 A: 地域ボード画像 + 透明な六角形 | 案 C': 区域タイル（7 種）+ 地域アイコン（8 種）を区域ごとに並べる（**採用候補**） |
| --- | --- | --- |
| 180° 回転（003 §2.3） | 画像を回すと、区域内の 4 マスの印刷（ボーナス）も 180° 回り、`slot 0` のボーナスが画面の右下に来る。003 は「`slot 0` は画面の左上のまま」と確定しているので**食い違う**。地域アイコン（A〜H の字）も逆さになる | 区域ごとに正立のタイルを置くので**食い違わない**（003 §2.3「区域タイルは 1 区域ずつの正立画像なので、回転しても区域ごとには回さない」） |
| 縮小盤面・ランダム配置 | 16 枚の画像（表 8、裏 8）が全部必要 | 7 タイルだけ。盤面の組み立ては `(row, col) → タイル種` の表から |
| 画像量 | 地域ボード 16 枚（980 × 810 で約 1.3 MB【実測】） | タイル 7 枚＋アイコン 8 枚（約 0.2 MB【実測】） |
| 印刷版との見た目 | 同じ（地域の外周の白い縁取りを含む） | 区域は同じ。**地域の外周の縁取りは付かない**ので、別途描く（§3.5） |
| 左右の接続の見せ方 | 画像の端で切れる | 同じタイルを複製して「ゴースト」を作れる（§3.7） |
| 実装の手間 | 画像の回転と、slot 印刷位置のずれの補正が必要 | 区域は 72 個の DOM。座標計算は 003 の式そのまま |

- 採用候補は **案 C'**。理由は上の表の 1 行目（回転で 003 と食い違わない）に尽きる。区域タイル 7 種は表面・裏面に共通（海 = 表の海／裏の標準海、陸 = 表の陸／裏の標準陸。画像で見る限り同一。**同一であることは実装時に目視確認**。【未確認】）。
- **案 A を選ぶ場合**は、003 の未確定事項 No.9（回転時の印刷位置の扱い）を「物理的な回転どおり（`slot 3 - k`）」に改める必要がある。→ 未確定事項 No.5。

#### 3.2 区域の幾何

`W` ＝ 区域の幅（`--pe-hex-w`、px）。区域の高さ `H = W × 503 / 435 ≒ 1.156 W`（タイル画像の比）。行の間隔は `0.75 H`、同じ行の列の間隔は `W`。003 §1.1 の `shift(row) = (row + P) mod 2`（`P` は盤面全体で 1 つ）を使う。

| 項目 | 式 |
| --- | --- |
| 区域の左端 | `left = (col + 0.5 × shift(row)) × W` |
| 区域の上端 | `top = row × 0.75 × H` |
| 盤面の幅 | `(W_cols + 0.5) × W`（通常 12.5 W、縮小は 9.5 W・6.5 W） |
| 盤面の高さ | `(5 × 0.75 + 1) × H = 4.75 H`（6 行） |
| 区域の中心 | `(left + W/2, top + H/2)` |

- 検証【実測】: タイル 435 × 503 を 12.5 × 4.75 並べると 5437 × 2389。`board_face` は 5428 × 2388。
- **この式は PHP と JS の二重実装にしない**。座標変換（オフセット ↔ ダブルド ↔ ピクセル）は `src/modules/js/board/geometry.js` に純粋関数（BGA のグローバルを使わない ES モジュール）として置き、003 の検証例を使った Node スクリプト（`scripts/check-board-geometry.mjs`）で検査する。004 §10 の「JS の純粋関数を Node で検査するか」は、**検査する**と本仕様書で決める（【提案】）。
- 区域の DOM 要素は `W × H` の箱に `clip-path: polygon(50% 0, 100% 25%, 100% 75%, 50% 100%, 0 75%, 0 25%)` を付け、六角形の中だけがクリックに反応するようにする（箱は隣と重なるが、clip-path で外側はヒットしない）。`data-cell`（003 §1.4 の `cell = row × W + col`）、`data-row`、`data-col` を付ける。

#### 3.4 キューブ（区域内の 4 マスと重ね置き）

- 通信確立したキューブは、`slot k` の中心に置く（003 §5.1。Z の順: 左上、右上、左下、右下）。発射拠点のある区域では左上に発射拠点コマがあり（§3.6）、キューブは右上（`slot 1`）から置かれる（作者回答 2026-10-20）。
- **同時確立で同じマスに重なる**キューブ（003 §5.2）は、マスの中心から右上へ約 12 % ずつずらして重ねて描く。重なりの順（下が先に置かれた側）は 003 のデータの順に従い、後のものを手前にする。重なった数が 2 以上のときは、マスの右下に小さな数字バッジ（「×2」）を出す。タップ／ホバーで、重なっているキューブの持ち主一覧を出す。
- **キューブの絵**: 原本のキューブ画像（`piecies/cube/`、48 × 56 px の等角図）は小さい。区域の幅 130 px のときマスは約 27 px、原本のキューブを等倍（タイル縮尺）で描くと約 14 px になる。**4 色の固定色で描いた CSS の角丸の正方形**（プレイヤー色の塗り、暗い縁、白い内側のハイライト）にする案を第一候補にする（解像度に依存せず、`--pe-hex-w` が小さくても 6 px 以上で読める）。原本のキューブ画像は、パネルのカウンターと凡例のアイコンに使う。見た目の好みなので作者に確認する（未確定事項 No.6）。
- キューブの色: プレイヤー色（青・緑・赤・黄）。**色だけに頼らない**ため、設定項目「Show player marks on pieces」（既定オフ）を `gamepreferences.jsonc` に用意し、オンのときキューブ・衛星コマに席順の数字（1〜4）を重ねる（未確定事項 No.13）。

#### 3.5 地域の外周

- 案 C' では地域の外周の縁取り（印刷版の白い太線）が無い。盤面データの `boardId`（A〜H）から、**隣り合う区域の `boardId` が違う辺**だけを集め、1 枚の SVG（盤面と同じ大きさ、`pointer-events: none`）に白い太線（幅 `0.03 W`、角は丸）で描く。区域の頂点の座標は §3.2 の式と六角形の頂点から出す。
- 地域の左右の接続（左端と右端の間）の辺は、ゴースト（§3.7）の境界にも描く。
- 地域アイコンの位置は、地域の `(1, 1)` の区域。180° 回転しても `(1, 1)` は動かない（003 §2.3）ので、回転の有無によらず同じ式で置ける。

#### 3.6 衛星コマと発射拠点コマ

- **衛星コマ**: 5 形状（HAMMER・RETRO・SCALLOP・CONCORDE・STEALTH）× 4 色（`piecies/satellite/`、約 228 × 125 px）。区域の中央に、区域の幅の約 0.45 倍の幅で描く（タイル縮尺 0.53 より少し小さい。4 マスにかからない大きさ）。同じ区域に複数の衛星がいるとき（001 §7-4、発射拠点への複数の打ち上げ）は、中心から 0.12 W ずつずらして重ねる。
- **向き**: 衛星の向きは 6 方向（003 §4.1、作者回答 2026-10-20）。原本の画像は、目視では**機首が左向き**に見える【未確認。実装時に 20 枚すべてで確認する】。機首が左向きの場合、CSS の `rotate`（時計回りが正）の角度は次のとおり。

| 向き（003 の識別子） | 画面上の向き | `rotate`（機首が左向きの原画） |
| --- | --- | --- |
| `NE` | 右上 | 120° |
| `E` | 右 | 180° |
| `SE` | 右下 | 240° |
| `SW` | 左下 | 300° |
| `W` | 左 | 0° |
| `NW` | 左上 | 60° |

  原画は立体（厚み）の描き込みがあり、斜めに回すと厚みの方向も回る。違和感が強い場合は、**回さずに左右反転（`NE`/`SE` は原画を左右反転、`NW`/`SW` は原画のまま）し、向きは区域の辺の上に出す小さな矢印（シェブロン）で示す**案に変える（未確定事項 No.7）。どちらの案でも、**所有者の衛星には向きを示すシェブロンを併用**する（回転が見分けにくいときの保険）。

- **向きの反転（反射）の表現**: 上下の端で `NE ↔ SE`、`NW ↔ SW` に反転する移動（003 §4.2）は、衛星コマが端の区域に達したとき**短い「はね返り」のアニメーション**（0.2 秒）で向きを変えてから次の区域へ進む。転回ではないので転回の効果音・演出は使わない。
- **発射拠点コマ**（`piecies/base/`、163 × 228 px）: 区域の**左上のマス（`slot 0`）の中心**に、区域の幅の約 0.2 倍の幅で描く。衛星コマとキューブより下の層。**発射拠点は 1 番目のマスを占める**（作者回答 2026-10-20、003 未確定事項 No.5）ので、発射拠点のある区域のキューブは右上（`slot 1`）以降に描かれる（§3.4）。他のプレイヤーが通信確立できる（先駆コスト、008 §3-4）ので、拠点の持ち主の色を縁に出す。
- 燃料の表示: 盤面上の衛星コマには数値を常時出さず、ホバー／タップで「Fuel R / C」（008 §7）を出す。`--pe-hex-w` が 96 px 以上のときは、コマの下に残量の小さなバー（細い 3 px）を出す。

#### 3.7 左右の接続と上下の反射の見せ方

- 盤面の左端と右端は接続する（003 §4.2、§6）。行がずれるため、**ずれた行の左端と、ずれていない行の右端に半区域ぶんの空き**ができる。この空きに、**反対側の端の区域の半分（ゴースト）を薄く描く**（不透明度 0.5、`pointer-events` は無効にせず、クリックは本物の区域（同じ `data-cell`）へ委譲する）。見た目に盤面が筒（円筒）状につながっていることが分かる。盤面の幅は増えない。
- 衛星が左右の端をまたいで動くときは、**端から出て反対側のゴーストから入ってくる**ように 2 段で動かす（0.25 秒ずつ）。
- 通信確立の前後の区域（008 §3-5）で端をまたぐ場合は、**両側に同じ区域を強調**（本物とゴースト）し、矢印も端で折り返して描く。
- 上端・下端は接続しない（反射する）。盤面の上と下に、薄い帯（6 px）に上向き・下向きのシェブロンを敷き、「ここで跳ね返る」と示す。「反射後の位置は通信確立の対象にならない」（003 §6.1）ので、帯の外側にハイライトは出さない。

#### 3.8 盤面コンテナ、拡縮、スマホでのスクロール

- 盤面は `#pe-board-viewport`（`overflow: auto`、PC では `visible` 相当で全体が収まる）の中の `#pe-board`（幅 `12.5 W`）に置く。
- **PC（`wide`、`medium`）**: 幅に収まるように `--pe-hex-w` を自動で決める（§2.2）。コンテナの右上に [−][Fit][+] のズームボタン（`--pe-hex-w` を 1.25 倍・0.8 倍、Fit は自動値）を置く。
- **スマホ（`narrow`）**: 既定の `--pe-hex-w` は 52 px（盤面 650 px、画面幅の約 1.7 倍）で、横スクロールして見る。ボタンは **[Overview]（画面幅に収める。約 31 px で、タップ操作の対象にはしない）**・**[Normal]（52 px）**・**[Large]（76 px）**。
  - 選択モード（打ち上げ、通信確立、配備先の選択など）に入ったとき、**選べる区域の外接矩形が収まる最大の段階**へ自動で切り替え、その位置までスクロールする（【提案】）。ただし、利用者が自分でズームした直後は上書きしない。
  - 横スクロールの初期位置は、**自分の発射拠点の区域**が中央に来る位置（左右が接続しているので、盤面を「円筒」として端をまたいでスクロールさせる案もあるが、実装が複雑なので初期は行わない。【提案】）。
- **bga-zoom を使うか自前で拡縮するか**（未確定事項 No.3）: bga-zoom は盤面コンテナを `element` にして `autoZoom: { expectedWidth: 12.5 × 144, minZoomLevel: 0.25 }` が使える。一方、(a) CSS zoom は BGA の autoscale と二重になる、(b) 姉妹では `position: fixed` の拡大表示が祖先の zoom で基準がずれた（姉妹 #52）、(c) BGA のガイドラインは「ズームボタンを避けレイアウトで解決する」方向（姉妹 009 が Guidelines A.5 として確認。**今回は未再確認**）。**暫定案: 自前の拡縮（`--pe-hex-w` の変更）。bga-zoom は使わない**。この場合、座標計算は常に `--pe-hex-w` から行い、`getBoundingClientRect` を使う処理は最小にする。**Studio で最初に検証する**。

#### 4.6 拡大表示（ツールチップとモーダル）

- **PC**: カードにホバーして 300〜500 ms 後に、zoom シートから切り出した大きな画像（幅 360、衛星カードは 540）と、**英語のテキストパネル**（§8）をツールチップで出す。
- **作者回答 2026-10-20（拡大表示が選択の邪魔になる件）**: 拡大表示は**すべてのカード**（手札・場・衛星・アクション・ミッション・褒賞・選択パネル・効果の窓。`Tooltip.bind` を通る全箇所）で共通に、**カードを覆わず、クリックを奪わない**。PC のホバー表示は `pointer-events: none` で、ホバー中のカードがない側の画面の端（左右）に固定して出す。マウス押下で閉じる。選択モード中は表示までの待ちを 900 ms に延ばし（通常 400 ms）、**右クリックで即時に出す**。ホバー表示のチップ（衛星カードの配備カード切り替え）は出さない（タップで開く表示では従来どおり）。
- **スマホ（タッチ）**: ツールチップは信頼できない（GameJs）。**タップで拡大表示を開く**（選択モード中は、タップは「選択」で、**長押し 500 ms** が拡大。選択モード以外はタップでも開く）。拡大表示は画面の空いた所をタップすると閉じる。
- 拡大表示は **`document.body` 直下**に出し、`position: fixed` の祖先に BGA の CSS zoom が効かないようにする。高さの上限は `100vh` ではなく **`window.innerHeight` からステータスバーを引いた値**（iOS の 100vh はツールバーを引かない値。姉妹 #52 で下が切れた）。効果テキストは枠内でスクロールさせる。
- 拡大表示の中身: カード画像、英語の名前、種類、コスト、名声、効果タイミング・効果タイプ・稼働条件、英語の効果文（002 の英語文案）、FAQ のある場合の裁定へのリンクは不要。
- 衛星カードの拡大表示には、配備されている全カードのチップを並べ、チップをタップすると、その配備カードの拡大表示に切り替わる。

### 7. アセットの加工（スプライト化）

#### 7.1 方針

- **形式は WebP（非可逆、品質 80、アルファあり）**。盤面のタイルとコマは**ロスレス**（絵が平坦で、ロスレスの方が小さいか同等）。PNG・JPG は使わない（Img: webp を「できる限り使う」。PNG/JPG は配備時に自動で WebP へ非可逆変換され、まれに問題になるので、手元で作った WebP を使う）。
- **2 段の解像度**: 通常表示用（base）は `img/` 直下、拡大表示用（zoom）は `img/zoom/` に置く（Img: サブフォルダの画像は既定では先読みされない。拡大を使うまで読み込まない）。**サブフォルダの使用は 004 §3「サブディレクトリなし」と食い違う**ため、Studio で確認する（未確定事項 No.9）。確認できなければ `img/` 直下に置き、先読みの総量が増える点を許容する（`dontPreloadImage` で外す案もある。GameJs）。
- **【2026-10-20 リポジトリ公開に伴い変更】生成物はコミットする。** `data/` は Git 管理外（作者の手元だけ）になり CI で生成できないため、`src/img/pe_*.webp`・`src/img/zoom/`・`sprites.js` をコミットし、CI と同期はコミット済みの画像を検査・転送するだけにする（`.gitignore` に残すのは `/build/` のみ。ただし CI の検査が読む `build/sprites/manifest.json` もコミットする）。原本を変えたら手元で `npm run build:sprites` して PR にする。以下は当時の方針。
- **（旧）生成物はコミットしない**。`data/` の原本から CI で生成する（004 §3、§12、姉妹と同じ作者の方針）。生成コマンドは `npm run build:sprites`、検査は `npm run check:sprites`。出力は `src/img/pe_*.webp` と `src/img/zoom/pe_*.webp`、対応表は `build/sprites/manifest.json`。`.gitignore` に `/src/img/pe_*.webp`、`/src/img/zoom/`、`/build/` を追加する。

#### 7.3 並び順（キー → シート・列・行）

生成スクリプトと画面のコード（JS）が**同じ式**で位置を求める。式は `scripts/lib/sprite-layout.mjs`（生成と検査が共用）と `src/modules/js/cards/sprite-layout.js`（画面）の 2 か所に置き、検査スクリプトが 2 つの結果の一致を確認する（姉妹の `sprite-layout.mjs` と同じ作り）。

- **プロジェクトカード**: `i = 番号 − 1`（0〜98）。base は `シート = ⌊i / 33⌋ + 1`、`j = i mod 33`、`列 = j mod 11`、`行 = ⌊j / 11⌋`。zoom は `シート = ⌊i / 30⌋ + 1`（`i ≥ 90` は `pe_zoom_misc`、`j = i − 90`）、`j = i mod 30`、`列 = j mod 6`、`行 = ⌊j / 6⌋`。
- **misc の並び**（base の 18 枚）: `PREV`（0）、A001〜A005（1〜5）、`AREV`（6）、M001〜M010（7〜16）、`MREV`（17）。zoom の `pe_zoom_misc` は P091〜P099（0〜8）、その後ろに同じ並び（9〜26）。
- **褒賞**: `i = 番号 − 1`。base は `列 = i mod 8`、`行 = ⌊i / 8⌋`。zoom は `列 = i mod 6`、`行 = ⌊i / 6⌋`。
- **衛星カード**: MOON 面は `R001B`〜`R005Y` を `(形状番号 − 1) × 4 + 色番号`（色は B = 0、G = 1、R = 2、Y = 3。0〜19）、色別プランは `R006`〜`R025` を `20 + (番号 − 6)`（20〜39）。base は 8 列、zoom は 6 列。
- **区域タイル**: 識別子の順（003 §3.1）`sea`、`land`、`deep_sea`、`reef`、`forest`、`mountain`、`snow` = 0〜6。4 列 × 2 行。8 番目のセルは空。
- 画面側の CSS は、セルの大きさに応じて `background-size: (列数 × 100)% (行数 × 100)%`、`background-position: (列 / (列数 − 1) × 100)% (行 / (行数 − 1) × 100)%` と**パーセントで統一**する（px と混在させない。CssPage で確認した Safari のずれの注意）。
- 衛星カードのキー（`R006` など）と色別プランの色の対応は 002 §6.2 のとおり（PHOBOS = 青、DEIMOS = 緑、EUROPA = 赤、GANYMEDE = 黄）。ゲームオプションで MOON 面か色別面かを選ぶ（001 §3）。画面側は「どの面か」の識別子（`R001B` など）をサーバーから受け取る。

#### 7.4 コマ・アイコンのシート（`pe_pieces.webp`）

| 区分 | 内容 | セル（px） | 並び |
| --- | --- | --- | --- |
| 衛星コマ | 5 形状 × 4 色（20 点） | 232 × 132 | 4 列（色 B・G・R・Y）× 5 行（HAMMER・RETRO・SCALLOP・CONCORDE・STEALTH） |

#### 7.5 生成スクリプトの仕様（実装は別 PR）

姉妹の `scripts/build-sprites.mjs`、`scripts/check-sprites.mjs`、`scripts/lib/sprite-layout.mjs` の構造を流用する（004 §12）。

- **入力の検査**: 期待するファイル名の一覧（プロジェクト 99 + `PREV`、衛星カード 40、アクション 6、ミッション 11、褒賞 24、タイル 7、コマ、アイコン）と `data/` の実在を突き合わせ、欠け・余りでエラー。寸法（カードは 715〜716 × 998〜999、衛星カードは 998〜999 × 715）が範囲外でもエラー。RGBA でないものもエラー。`P037 @4x.png` は例外表で扱う（正しい名前 `P037` に対応）。`data/` は読み取りのみ。
- **縮小**: `sharp` の `resize(w, h, { fit: 'fill', kernel: 'lanczos3' })`。セルは 1 枚ずつ縮小して `composite` で透明なキャンバスに貼る。`webp({ quality: 80, effort: 6, alphaQuality: 100, smartSubsample: true })`（ロスレスのシートは `lossless: true`）。品質は 75〜85 の範囲で画質を見て調整してよい（既定 80）。
- **決定性**: 同じ入力から同じバイト列になること（`--verify-determinism` で 2 回生成して比較）。`sharp` のバージョンは `package-lock.json` で固定する。環境が違うと出力が変わりうるので、検査は容量・寸法・存在だけで、バイト一致は要求しない。
- **対応表（`build/sprites/manifest.json`）**: キー → シート・列・行・セル寸法・シート寸法。画面の JS は式（§7.3）で位置を求め、対応表は検査にだけ使う。
- **検査（`check-sprites.mjs`、005 §2.9 の A1）**: 生成後の `src/img/**` について、(1) 1 ファイル **2,000,000 B 以下**、(2) 総量 **15,000,000 B 以下**（目標は 10,000,000 B 以下で、超えたら警告）、(3) 1 辺 **4096 px 以下**、(4) ファイル名に空白・括弧・大文字の拡張子がない、(5) `img/` 直下のファイルが **10 個以上なら警告**、(6) 対応表の全キーがシート内に収まる。005 の値（2,000,000 / 15,000,000 / 4096 / 10 個以上で警告）と一致させる。検査を `scripts/lint/` に置くか同期側だけに置くかは 005 の未確定事項 No.6 のまま（T-006 で確定）。
- **CI**: `npm ci` → `npm run build:sprites` → `npm run check:sprites` を、同期（T-006）の前に実行する。生成物は同期のアーティファクトで、コミットしない。生成時間の目安は姉妹で十数秒（本ゲームは約 200 枚で数十秒と見込む。【推定】）。
- **ローカルの画面確認用**: 実装者が手元で `npm run build:sprites` して `src/img/` に出力し、Studio へ手動同期できること（姉妹と同じ）。

#### 7.6 地域ボード・トラックの画像を使わない理由

- 地域ボード 16 枚（約 1.3 MB）は §3.1 の理由（180° 回転で 4 マスの印刷が回る）で使わない。**使うとすれば、ゲームオプション「Earth（回転なし）」だけ**という案もあるが、経路が 2 つになり検査が増えるので採らない。
- トラック 2 枚（約 4.5 MB、1500 × 2400 の縦長）は §2.3 の理由で使わない。
- 箱画像（4.5 MB、1919 × 2600）は `img/` に置かない（メタ画像は管理画面から登録。§9）。

### 8. 多言語対応

#### 8.1 UI の文言

- **UI 文言は英語を原文**とし、BGA の翻訳機構で日本語化する（CLAUDE.md、004）。JS は `_()` で包む（GameJs: 「`_()` で包まないと翻訳対象にならない」）。PHP は `clienttranslate()`。
- 動的な値は `${name}` の形の置換で渡し、文を組み立てない（翻訳の語順のため）。ログに出すカード名は、英語名（002 の `name_en`）と、必要なら小さなカード画像のアイコン。

#### 8.2 カード画像の文字（日本語の印刷）

カード画像（`data/cards/`）の券面は日本語で印刷されている。選択肢:

| 案 | 内容 | 長所 | 短所 |

### 10. スマホ対応で姉妹が苦労した点の先回り

姉妹 `minimum-journey-bga` の UI 修正 PR（#36・#37・#40・#52）と BGA の Mobile ページから、本ゲームで先に避けることをまとめる。

| # | 姉妹で起きたこと | 本ゲームでの対策 |
| --- | --- | --- |
| 1 | カードの大きさを `cqw`（コンテナ幅）基準にしたところ、スマホ幅で山札の枠とカードの大きさが食い違った（#37） | 大きさの基準は JS が `ResizeObserver` で測って入れる px の CSS 変数（`--pe-root-w`、`--pe-hex-w`、`--pe-card-w`）。`cqw`・`vw` に依存しない（§2.2） |
| 2 | bga-cards 1.x のカードの面が、`CardManager` の `cardWidth`・`cardHeight`（120 × 168）の大きさのまま、縮小表示で左上へはみ出した（#40）。山札の枠 `--width` / `--height` も同様（#36） | `--bga-cards_card-width` / `-height` と山札の `--width` / `--height` を、実寸の変数で **`!important` で上書き**する。bga-cards の CSS は後から注入されるため、詳細度を上げて読み込み順に頼らない |
| 3 | 拡大表示が `100vh` を使い、iOS のツールバーのぶん下が画面外に切れた（#52） | 高さの上限は `window.innerHeight` からステータスバーを引いた値（§4.6） |
| 4 | 拡大表示が `position: fixed` だが、ゲーム領域の祖先の `transform` / `zoom` で基準がずれた（#52） | 拡大表示・ツールチップは `document.body` 直下に出す |
| 5 | 山札・スロットの点線の枠を `border` にしたため、カードが隣より 2 px 下にずれた（#52） | 点線の枠は `outline` か、内側に収まる `box-shadow inset` で描く（レイアウトに影響しない） |
| 6 | 枚数バッジがラベルに重なって隠した（#52） | バッジとラベルの位置関係を設計時に決める（バッジは右上の外側、ラベルは下へ） |
| 7 | 流れの外に出る（絶対配置の）カードのせいで、枠が潰れる／左へずれた（#37） | 山札・スロットの枠は幅と高さを固定し、`flex: 0 0 auto` と `min-width: 0` で縮まないようにする |
| 8 | PC で 4 人の領域を横に並べたとき、1280 px の画面では幅が足りなかった（姉妹 009 §7.4） | 本ゲームは盤面が幅いっぱいを使うので、相手のブロックは**人数が多いほど折り返す**。ブロックの最小幅（約 340 px）を決めて `flex-wrap` |
| 9 | ホバー専用の情報がタッチで見えない | 必要な情報は拡大表示（タップ）にも出す。ホバー専用のスタイルは `.notouch-device` を前置（Mobile） |
| 10 | 背景画像の `background-position` が px と % で混ざり、Safari で数 px ずれる | `background-size` / `-position` は % に統一（§3.3、§7.3） |

追加で本ゲーム特有の注意:

- **盤面の横スクロールと、BGA のページ全体の縦スクロール・ピンチが競合する**。盤面コンテナは `touch-action: pan-x pan-y`（ブラウザの標準のスクロールのみ）にし、独自のドラッグ処理は入れない。ズームは段階ボタンだけにして、ピンチズームは使わない（Mobile: `touch-action: none` はジェスチャーを自前で処理する要素にだけ）。
- 区域のタップは `click` ではなく **Pointer Events**（`pointerup`）で扱い、`pointermove` が閾値（8 px）を超えたときは選択としない（スクロールとの区別。Mobile が推奨）。
- 回転端末（縦横の切り替え）や、キーボードの表示で `ResizeObserver` が走るので、`--pe-hex-w` の更新はデバウンス（100 ms）し、アニメーション中の再計算を避ける。
- 実機の確認項目（受け入れ条件に含める）: 幅 360・390・412・768・1024・1280・1920 px、DPR 1・2・3、ライト／ダーク、2・3・4 人、観戦、縮小盤面（9・6 列）、180° 回転ありの盤面、リロード後の復元。

### 11. ダークモード・アクセシビリティ・アニメーション

- **ダークモード**【確認】（姉妹 009 が CssPage で確認）: `html[data-theme="dark"]` で判定する。`@media (prefers-color-scheme: dark)` は BGA の切り替えを無視するので使わない。カード画像と区域タイルは共通。背景・枠・バッジ・プレースホルダー・ツールチップ・ハイライトの色を CSS カスタムプロパティにして切り替える（区域タイルは明るい地に濃い縁があるので、盤面の背景は両方で一定の暗い紺にし、テーマで変えない）。
- **色だけに頼らない**: 選択可否（§3.9）、使用済み（× のマーク）、横向きカード（回転 + グレー）、プレイヤー色（設定の「Show player marks on pieces」で席順の数字を重ねる）。
- **アニメーション**: bga-animations（CodeSharing）を使い、通常 0.5 秒、最大 0.8 秒。同時に動くものは並列（全衛星の移動、燃料の消費）。`bgaAnimationsActive()` が偽のとき（リプレイの高速再生、観戦のジャンプ）は即座に最終状態にする。ループ・バウンドなどの装飾はしない（反射のはね返りは短い 0.2 秒）。
- **観戦者**: `spectatorMode` クラス（姉妹 009 が確認）で、自分の領域を出さず、全プレイヤーを同じ大きさで席順に並べる。非公開の情報（手札、ミッション、プレビュー）を出さない。
- **ログ**: 誰が何をしたかをカード名・区域（行と列、または地域名）で書く。区域は「row r, col c」の座標だけではなく、地域（A〜H）と種類（Sea など）も付ける。ログ中のカード名にホバー／タップで拡大表示を出す。

## エッジケース

- **縮小盤面（9 列・6 列）**: 盤面の幅は `(列数 + 0.5) W`。左右の接続は縮小後の端同士（003 §2.2）。ゴーストも同じ式で作る。6 列（2 人用の最小）でも 12 列と同じ `--pe-hex-w` の上限・下限を使い、余白は左右に均等に取る（盤面は中央寄せ）。
- **同じ区域に衛星が多数いる**（発射拠点に連続して打ち上げた、通信確立の候補が複数）: 重ねる位置を 0.12 W ずつずらし、5 機以上は重ねずに「+n」のバッジ。タップで一覧。
- **区域が小さい（`--pe-hex-w` が 52 px 以下）**: キューブは CSS の正方形（約 11 px）、衛星コマは区域の幅の 0.45 倍（約 23 px）で描く。燃料バーと向きのシェブロンは出さない（タップで詳細）。
- **180° 回転した盤面**: 区域ごとに正立のタイルを置くので、見た目の特別扱いは無い。地域の外周の SVG も `boardId` の差だけで描けるので回転を意識しない（§3.5）。
- **盤面が動的に変わらない前提**: 区域のタイルと地域は `setupNewGame` で決まり、ゲーム中は変わらない（004 エッジケース）。リロードで同じ盤面になること（DB に保存した配置から描く）。
- **スマホで盤面が画面外へスクロールしたとき**: ステータスバーの指示は BGA の標準（画面上部）なので見える。選択のボトムシートは盤面コンテナの下に貼り付き（`position: sticky`）、盤面を見ながら操作できる。
- **ズーム中に選択モードへ入る**: 利用者が直前に手動でズームしたとき（5 秒以内）は自動切り替えをしない。
- **リロード時の復元**: 盤面・手札・衛星の状態はサーバーの値から再描画する。拡大表示・ボトムシート・選択のプレビューは閉じた状態で復元し、選択中の状態（009）のときだけ再度開く。
- **画像の読み込み失敗**: スプライトが読めないとカードが透明になる。カードの要素に、カード名の文字（英語）のフォールバック表示を重ねる（`::after`）。致命にならない。
- **日本語の効果文が画像に含まれる**: 画像に誤りがあってもコード側では直せない（エラッタは `data/` の更新と再生成。CLAUDE.md の一次情報の優先順位に従う）。
